当前操作以 [网络使用指南](network.md) 为准，版本范围见 [v0.1.5 待发布说明](releases/v0.1.5.md)。下方阶段记录中的“尚未开放”等结论只描述当时状态，后续进展与当前汇总优先。

方案见 [多网卡与中转设计](network-and-tunnel-design.md)。本文件区分已实现内容、验证结果与后续阶段，不代表整份方案已经完成。

## 1.1 当前进度

当前开发版已接通网卡观测、计费接口选择、指定监听与直连出口、SOCKS5/SS-2022/SSH/WireGuard 外部出口、托管 SS-2022/WireGuard 双端中转、mita 自动部署及 WireGuard 单用户接入。固定转发当前开放 TCP；UDP/TCP+UDP 暂不开放。已撤回自编译内核方案，SS-2022 出口使用官方 1.14.1 或兼容的 1.14.x 稳定版，不自动替换已选内核。新能力按内核版本、架构和本机条件预检，未启用时保留现有节点、订阅和计费行为。剩余运行验收范围列在 1.4；历史实验不等于发布验收。

网卡身份文件为 agent 状态目录下的 `network-interfaces.json`，不含认证凭据。每次上报前先持久化序列与身份；文件损坏显示采集错误，不静默重置。Agent 停止时关闭删除事件监听。小时历史复用现有保留策略，日历史沿用已有行为。

## 1.2 容量与边界

单次最多 128 个接口，每接口最多 32 个地址；单次 netlink dump 最多 4 MiB，有接收超时和通知读取预算。超过清单上限报告不完整，不按残缺清单宣布所有其他接口消失。

单服务器最多保留 2048 个接口身份及 4096 个采集来源；达到上限明确报告观测错误并保留旧配额流程。页面目前展示最近 256 条接口记录（当前接口优先）。历史分页和受控归档已接入，归档不删除身份或账本，见 1.3.29。选定和待选计费接口在采集清单超限时优先保留，但残缺清单不能用于新接口策略。

默认路由信息只描述 main 表，不判断复杂策略路由下的实际运营商账务边界。默认不合并接口，不改变公网访问地址。选择计费接口时拒绝已知上下级关系、回环、隧道与其他接口混选，复杂拓扑仍需管理员确认计量层。已生效策略也持续检查拓扑，重叠时暂停相关服务器增量并重建基线。首次采样与重建基线无法还原此前缺失的流量。

单服务器计费策略最多 4096 个不可变版本，计费采集注册身份最多 4096 个；目前只允许追加版本，达到上限明确报错。待结算快照保存在 agent 的 `state.json`，未确认不丢弃；重复回执按批次内容校验。切换等待期间服务器账本暂停更新，节点与分享计量继续；收到确认后从新基线累计。异常和恢复沿用审计日志保留策略。

已切换过的 agent 使用新扩展传输旧模式计数，旧字段保持为零；旧控制端不会把扩展误计为旧来源。新控制端遇到不匹配的 agent 策略会报告计量不完整。这里只提供账务保护，签名验证后的版本降级主动拦截已接入，见 1.3.25 节；完整维护容器升级路径尚待联调。

### 1.3.1 出口绑定预验证

`scripts/test-network-bind-container.sh` 已在 Linux ARM64 上验证官方 sing-box 1.12.14。测试二进制来自官方 Release，其归档 SHA-256 与官方元数据一致；脚本要求调用者提供已验证的匹配架构二进制。

容器无外网，内部建立双网卡与独立落地网络命名空间。实际代理以非 root 身份运行，沿用生产 seccomp 过滤器及 NET_BIND_SERVICE/NET_RAW 能力；独立 nft 计数检查真实出口接口与节点 routing_mark。

| 项目 | 结果 |
|---|---|
| 默认路由 | TCP/UDP、IPv4/IPv6 均走首选接口 |
| 指定第二张网卡 | 两种传输和地址族均走第二张网卡 |
| 网卡与源 IP 同时指定 | 出口接口及对端看到的源 IP 均符合配置 |
| 仅指定源 IP | 源 IP 符合配置，但仍走原首选路由；不能代替网卡绑定 |
| 接口不存在、源 IP 不存在、接口关闭 | 新建连接失败，测试出口上没有旁路数据包 |
| 原有节点标记 | 正确保留 routing_mark |
| 业务 DNS | 每节点独立 resolver 与缓存，UDP/TCP、IPv4/IPv6、UDP 截断后 TCP 重试均保持出口与 mark |
| 域名业务 | TCP 和 UDP 通过各自节点出口；一侧接口关闭后，另一侧节点仍可用 |
| 地址族 | IPv4-only/IPv6-only 同时约束解析和字面量 TCP/UDP 目标，不能绕过解析策略 |
| 已有会话 | 接口关闭及已安装的节点 mark 阻断规则均阻断已有 TCP/UDP、IPv4/IPv6 会话 |
| 接口替换 | 删除重建同名、同 ifindex 接口后，采集器给出新 ID；事先安装的节点阻断规则继续生效 |

DNS 与会话部分现在调用实际的 `ResolveBinding` / `CompileDirect` 生成配置，再由官方 sing-box 1.12.14 执行。实验也发现测试内核在接口关闭后撤销 IPv6 地址及路由；测试夹具会显式重建，产品不得自动修改这些宿主配置。

早期接口替换实验在删除前主动安装阻断规则；后续补充的持续 guard 实验见 1.3.3，验证了自动检测、已有连接阻断和 watchdog 恢复。生产配置编译器的 SS-2022 实际路径补测见 1.3.4，完整 systemd 节点链路见 1.3.7。Reality 认证握手的实际流量仍未验证，新能力尚未开放到面板。AMD64 已完成编译检查，尚未执行该网络实验。

### 1.3.2 绑定配置与编译基础

新增 `internal/networkconfig` 的节点网络字段、不可变出口引用、直连配置、显式 DNS 和源地址所属接口身份。`internal/netinventory.ResolveBinding` 使用新鲜完整的本机快照解析稳定 ID，检查链路、地址归属、重复地址、可用性及服务器 IPv4Only；返回的应用候选与输入配置分离。仅源地址绑定保留原路由语义。

网络快照增加可选 `usable_addresses` 子集。采集器根据地址 flags 和 lifetime 排除尚在校验、校验失败或已失效地址，但继续展示完整地址清单。未上报可用性信息的旧快照仍可用于原有观察/计费，不能用于新增地址绑定。

`internal/core.CompileDirect` 生成独立出口、DNS、地址族拒绝与解析规则，以及保留计费 mark 的 Dial Fields。后续已接入 `BuildConfig` 与 desired 传输，见 1.3.4；数据库后续接入见 1.3.5，面板入口仍未开放。

测试覆盖接口改名、替换、地址转移、重复地址、过期快照、地址未就绪、IPv4Only 冲突、未解析身份和源地址绑定语义；Linux 容器验证地址 flags/lifetime 解析与真实配置执行。上述增量完成后再次通过 `go vet ./...`、`go test ./...`、两项 Linux ARM64 网络实验，以及 Linux amd64/arm64 的控制端和 agent 构建；本轮未修改前端。

### 1.3.3 持续网络保护基础

新增 `internal/networkguard` 的绑定计划、受控 nft 编译及独立监测循环。`internal/netinventory.Watch` 订阅链路和地址事件，合并有界突发通知，流失效时明确终止续期。采集器支持并发串行化，计费偏好与业务绑定接口分别保留；主应用流程已登记业务绑定 ID。

`inet ctlvps_network` 使用优先级 -155，早于现有通用出站/DNS 放行与计量。每个绑定的默认状态为阻断，健康时续期 6 秒；接口/地址事件先撤销受影响节点租期，已有连接也受限制。观察器退出或卡住后，内核无需依赖用户态停止代理即可使租期过期。同名、同 ifindex 的替代接口不能复用旧身份；名称或其他实际绑定参数变化后等待重新应用。

`internal/proxyguard` 记录网络计划与静态规则摘要，续期和撤销都校验应用令牌；相同令牌和内容可幂等重试。正常的限时放行元素不构成防火墙漂移，永久或超长放行会被拒绝。watchdog 恢复的是空租期规则，原健康状态不会被重放。网络应用意图在修改规则前持久化，避免失败后恢复更旧的绑定。节点 mark 定义已统一到 agentproto，原 nft 对外入口保持不变。

隔离 Linux ARM64 实验调用这些实际组件与 sing-box，已验证：自动链路丢失检测、已有 TCP/UDP IPv4/IPv6 阻断、无关节点继续工作、原接口恢复、同名同 ifindex 替换持续阻断、新应用恢复、旧令牌拒绝、同令牌重复应用、规则修复默认关闭，以及没有监测任务时的租期过期。事件处理与防火墙恢复有异步时延，不能表述为零窗口切换。Snell 的规则生成已预留，真实 Snell/cgroup 组合尚待验证。

agent 主流程的后续接入见 1.3.4，数据库后续接入见 1.3.5。管理写 API/UI 尚未开放新绑定，现有节点的监听/出口行为不变。独立卸载器已补充自有网络表清理、dry-run 预览与两端隔离测试。

本阶段已通过全量 Go 测试/静态检查、采集器与 guard 的并发检查、Linux ARM64 网络实验和真实 systemd/nftables 容器的 18 项卸载场景。Ubuntu 24.04 nft 1.0.9 与 Alpine nft 1.1.5 的租期语法和时间字段均核验；两版的集合/链声明顺序不同，摘要已规范化声明顺序，仍保留规则顺序以检测行为变更。并发采样不会复用序列，更新计费选择也不会移除独立登记的业务绑定接口偏好。

### 1.3.4 正常配置编译与 agent 应用流程

`NodeSpec.network` 传输结构化监听策略、不可变直连配置引用及配置正文；本机解析结果使用 `json:"-"`，不能从控制端注入。省略网络字段时旧 JSON 和摘要语义保持不变。`BuildConfig` 编译实际监听 IP、节点独立出口及 DNS、解析后的私网拒绝、字面量地址族限制，并给 Reality handshake 附上相同 Dial Fields。当前绑定版本检查仅接受已实验的 sing-box 1.12.14；Snell 仍不开放绑定组合，也不会静默升级内核。

agent 的独立监测任务与整个 Run 生命周期一致，不依赖心跳 HTTP 或状态保存锁。退出时先撤销租期、停止任务，再关闭采集器；同一次系统启动内重启时只读取根权限保存的已应用计划，重新采样后才可能续期。接口改名等变化会触发重新收敛，即使控制端 desired 摘要没有变化。接口身份无法可靠延续时保持阻断。

应用先执行节点计量/配额封禁和根权限出站策略，再发布待应用阻断计划。改变过的凭据、监听、出口或本机权限参与配置指纹；待应用节点即使网卡健康也不能续期。没有变化的已应用节点可继续续期。缺卡候选从本轮核心配置中排除，其他节点继续应用；只有成功应用的内核才能激活对应候选。失败或移除的绑定保留阻断，直到其配置变更成功；共享进程可能因此重启，不能承诺其他节点无中断。

guard 规则本身安装失败时，额外停止并禁用相关受管内核，影响该内核的共享节点；停止失败也返回错误。旧版按端口独立进程的计量迁移一旦涉及新网络绑定，失败后保持这些旧进程停止，避免没有新节点 mark 的进程绕开保护。`NetworkDesiredRevision/Hash` 在执行变更前持久化，部分失败不会使旧代次恢复合法；重试须为相同内容，主动回退须由控制端产生新代次。全量应用结果仍独立报告，不能把记录意图当成应用成功。

新增诊断字段报告节点绑定错误和观察任务停止。完整能力协商、页面状态、实际 systemd/agent/controller 联调与升级降级入口仍待补齐；当前并未向管理员开放新绑定能力。

验证分两层：Go 测试验证应用顺序、失败内核不激活、凭据撤销后回滚仍阻断、缺卡不吞掉其他节点与配额操作、无变更不重装规则、改名重新编译、观察任务停止、旧计量迁移以及失败代次跨进程重放保护；隔离 Linux ARM64 实验使用未经改写监听/路由/出口的生产 `BuildConfig`，在另一命名空间运行客户端，验证两个独立 SS-2022 节点的指定监听 IP、独立 DNS、TCP/UDP IPv4/IPv6 出口，以及待应用节点阻断而同进程已应用节点可用。Reality 目前通过官方配置检查器，完整认证会话仍待验证。

### 1.3.5 控制端持久化、地址继承与旧操作兼容

数据库 v14 增加服务器所属的 `egress_profiles`、不可变 `egress_profile_revisions` 和 `node_networks`。设计中的 `nodes.network` 是逻辑字段；落库使用独立关联表，以外键约束节点、出口和版本属于同一服务器。绑定创建/更新/清除使用 CAS 版本，清除后保留版本号，防止旧表单恢复过时配置。旧数据库迁移后所有已有节点的网络字段仍为空，不自动创建出口或改变地址。

目前只保存经严格结构校验的 direct 配置，不接受任意核心 JSON、detour、路径或命令。单服务器最多 128 个配置，每个配置最多 4096 个不可变版本。修改配置生成新版本，已绑定节点继续引用原版本；停用配置会阻断引用它的节点。被节点引用的配置不能删除，服务器与节点删除按外键清理。后续新增分享目标或转发引用时，还须扩展依赖约束，不能只检查当前节点表。

节点及出口版本在同一 SQLite 读快照中加载，避免并发解除引用和删除时混用数据。普通节点编辑、凭据重置、分享暂停/撤销/重发与目标恢复均保留原网络设置；显式覆盖的访问地址不会被服务器地址更新或 agent 心跳覆盖。继承地址的更新由数据库条件控制。客户端订阅仅使用实际访问地址，不包含服务端绑定或出口正文；分享成员的节点视图隐藏这些内部字段，管理员可读。

新增测试验证 v13 升级、同服务器引用、不可变版本、并发 CAS、失败创建回滚、删除依赖与清理，以及真实分享生命周期和旧 API 编辑。分享重发与恢复仍轮换撤销过的凭据，不改变原节点身份、端口、出口版本或独立访问地址。分享目标自身的网络默认值和自动部署规则仍待实现。

### 1.3.6 配置版本保护与原子发布

数据库 v15 增加服务器的网络绑定版本要求。第一次保存非空绑定就在同一事务内记录要求，清除绑定或删除最后一个节点不会清除它。原因是 agent 仍可能需要清理本机规则；未来降级流程必须确认清理完成，不能仅按“当前没有节点”判断可降级。

绑定配置及其后续清理配置携带 `network_binding_version: 1`，该字段参与摘要。每次请求 desired 时，Linux agent 显式声明支持的版本；控制端同时检查数据库要求和待发配置，在返回正文或 304 前拒绝旧客户端。不能用缓存的心跳能力代替本次请求声明。agent 本地保存已接受的版本要求，即使较旧控制端产生更大的 revision，也不能因省略该字段而把绑定变成默认直连。未启用绑定的服务器继续省略字段，保持原有摘要语义。

该版本字段声明配置理解能力，实际可用性仍须同时检查锁定/安装的内核、计量、本机策略、网卡与保护规则。当前没有因此开放新绑定入口；内核版本设置的事务检查见 1.3.8，维护入口的主动降级拦截和完整能力视图尚待实现。

常规发布与管理员强制重发改为在同一数据库事务内写入完整正文和版本号，不再插入 revision 为零的正文后补写。发布比较构建前读到的最新版本；并发发布完成后，旧构建必须重新读取并重建，不能追加一个较新的版本号来覆盖新内容。去重也在事务内判断，失败重试有次数上限。此处解决发布顺序与正文完整性，保存后尚未发布的窗口与持久化队列见 1.3.9。

新增测试验证旧 agent 请求、缓存能力失效、304 不绕过检查、最后一个节点删除后的版本保留，以及 agent 重启后拒绝旧控制端语义。并发发布测试主动暂停一次旧构建，先完成新绑定发布，再恢复旧构建，确认最新绑定不被覆盖；数据库拒绝正文补写时，发布与强制重发仍能一次写入可通过 agent 校验的完整配置。

本轮全量 Go 测试、`go vet ./...` 与 store/desired/share/agent/API 等相关包 race 检查通过；控制端与 agent 的 Linux amd64/arm64 构建通过。额外在无外网、只读文件系统且删除全部 Linux capabilities 的 ARM64 容器中验证了实际 Linux 客户端的逐请求版本声明与跨重启保护。本轮没有前端改动，也没有重跑已完成的代理流量实验；完整 systemd 部署和 Reality 会话仍待验证。

### 1.3.7 隔离传输、完整 systemd 链路与协议对照

完整联调发现并修复了两处单元测试未覆盖的生产问题：

1. Linux 根进程的 HTTP 客户端设置了绑定版本头，但隔离网络子进程的字段白名单没有传递它。现在只在私有管理请求 `GET /api/agent/v1/desired` 中传递明确支持的版本；旧调用者不伪造能力，公共下载、心跳与任意其他头不扩散该字段。`TestNetworkContractContainer` 在真实低权限子进程、seccomp 和 HTTPS 下验证。
2. 节点端口自动开放将新建的 `inet ctlvps_network` 保护表误判为其他管理器的入站防火墙。现在精确识别该自有表，不修改其中的规则；其他 family 下的同名表仍按外部规则处理。真实默认拒绝的入站防火墙与网络保护表组合已通过部署。

新增 `scripts/test-network-systemd-container.sh` 和 `scripts/network-systemd-test`。无外网的 Linux ARM64 容器运行真实控制端 API、数据库及凭据字段加密、agent 二进制、隔离 HTTP 子进程、systemd 代理服务和官方 sing-box 1.12.14。测试的 agent 外层 unit 是最小夹具，代理 unit 和安全策略由生产代码生成；网络管理配置及安装入口的表单不是本实验的覆盖范围。

测试默认保留官方 sing-box 客户端路径。它在首轮收发通过后，重复连接中出现 `bad request salt`。另用只含上游库的临时 Go 模块固定 sing-shadowsocks2 0.2.1 与 sing 0.7.14，以 `net.Pipe` 控制首个 Write 返回时机：同一份有效响应在 Write 返回后被接受，在返回前被拒绝；AES-128、AES-256 均复现。该最小实验没有 VpsCT、网卡绑定或 nft 规则。源码证据是 sing-box 的 [实际客户端调用路径](https://github.com/SagerNet/sing-box/blob/v1.12.14/protocol/shadowsocks/outbound.go) 使用 `DialEarlyConn`，其 [锁定实现](https://github.com/SagerNet/sing-shadowsocks2/blob/v0.2.1/shadowaead_2022/method.go) 在发送请求后才保存响应校验所需的请求盐值。它证明该库存在相同的时序失败条件；没有修改或修复分发的上游二进制。

使用另一个独立官方客户端 shadowsocks-rust 1.25.0 对照，发行归档 SHA-256 与官方 Release 元数据核验一致。客户端只用于夹具，不作为产品新增运行组件，也不替换生产内核。显式设置 `NETWORK_TEST_CLIENT=shadowsocks-rust`、`SSLOCAL_BIN` 和 `SINGBOX_BIN` 运行；原 sing-box 客户端路径继续保留，没有通过重试忽略协议错误。

对照客户端下完成以下实际链路验收：

| 场景 | 结果 |
|---|---|
| 两个独立 SS-2022 分享 | 指定监听、独立 direct 出口；TCP/UDP、IPv4/IPv6、域名及 DNS 截断后 TCP 重试通过 |
| 响应时序 | 请求后读响应及只等待目标主动问候均通过 |
| 账务 | 两个分享的独立上下行计数经真实心跳进入各自账本 |
| 控制端返回 503 | 已应用服务保持运行；本机监测独立撤销失效网卡租期，另一节点可用 |
| 原接口恢复 | 夹具恢复内核撤销的 IPv6 地址/路由后，原身份恢复业务；产品不修改宿主路由 |
| agent 停止与重启 | 停止撤销租期；veth 身份不可证明连续时保持阻断；重新上报后显式创建新出口/绑定版本才恢复 |
| 网卡改名 | 稳定 ID 保留，同一 desired 摘要触发实际代理进程重新应用，之后两侧收发恢复 |
| 分享暂停/恢复 | 暂停同时阻断 TCP/UDP，另一分享继续可用；恢复后业务正常 |
| 删除最后节点 | 空的版本化网络计划生效，共享代理进程停止 |

veth 在 agent 停止期间没有可证明连续的设备身份，因此本实验不能声称它在离线重启后自动恢复。物理设备路径与 MAC 可可靠匹配时的身份保留、计数代次重建，以及 counter generation 不影响业务绑定身份，另由采集器和 guard 测试覆盖。真实物理网卡重启恢复、AMD64 网络运行和 Reality 认证会话仍待验证。

SS-2022 **服务端绑定与上述独立客户端**的通过，不代表锁定 sing-box 的 **SS-2022 outbound** 通过；后者不得因此开放。排期按设计 1.3 节拆分，不让这一协议实现阻塞已验证的多网卡和基础转发。

### 1.3.8 内核版本设置与绑定的双向检查

保存整批设置前先校验全部可编辑键，再在同一数据库事务中检查内核版本并写入。只要仍有非空节点网络配置，包括暂停节点，就拒绝把 sing-box 改为未通过绑定版本验证的版本；错误返回 409，其他设置不会部分保存，也不发布新的 desired。默认版本与配置编译器共用常量。

新增或修改绑定也在其保存事务内检查当前锁定版本，防止“先检查支持，再与版本修改并发保存”产生不兼容配置。显式清空绑定仍可执行，清空后的记录不算活动配置。这个入口检查没有替代 agent 本机预检，也没有完成 agent/控制端降级、卸载、升级锁或资源清理确认流程；持久化的绑定协议版本要求继续保留。

测试覆盖不兼容版本双向拒绝、暂停节点、默认与等价版本、显式清空、数据库写入失败的整批回滚、并发版本/绑定更新，以及 API 拒绝时没有配置发布。未启用新绑定的旧配置仍可选择原有内核版本。

本轮通过全量 Go 回归、原生及 Linux ARM64 静态检查、HTTP 隔离层/采集器/guard/store/API/desired 的 race 检查；控制端和 agent 均通过 Linux amd64/arm64 构建。完整 ARM64 systemd 实验使用上述独立客户端通过，原 sing-box SS-2022 客户端失败记录保留。本轮没有前端源码改动，沿用此前已构建前端；未将新绑定开放到面板。

### 1.3.9 持久化发布队列、操作与精确回执

数据库 v16 增加服务器网络代次及已发布代次，同时作为每服务器一条的持久化发布队列。绑定创建、修改、显式清空、出口停用和绑定节点删除在保存事务内递增代次。已经启用网络功能的服务器，其旧部署节点增删、凭据/监听/启停修改、分享状态、服务器运行设置和相关内核设置也进入相同队列。普通心跳、访问地址观测、流量累计和无关设置不触发发布，未启用网络功能的旧服务器仍不携带新字段。

发布从读取服务器设置前开始核对代次，构建完成后同时比较当前代次与先前 desired revision。这样即使新配置保存后控制端尚未发布，较早构建也不能覆盖新意图或恢复已撤销凭据。完整 desired、已发布代次和相关操作的回执标识在同一事务提交；失败回滚不会留下“发布成功但没有可匹配回执”的状态。控制端启动及每 5 秒扫描队列，每批最多 64 个服务器并限制总执行时间；控制端发布失败采用带抖动的退避，最多自动尝试 8 次，不代表 agent 应用失败的重试预算已同步改造。

`RequestNodeNetwork` 将绑定编辑、操作和审计一起提交，保存失败不改变任何一项。每服务器操作记录上限 4096；记录只保存请求摘要及必要状态，不复制密码或出口正文。相同 operation_id 与相同请求返回原操作，即使节点已删除；相同编号配不同请求拒绝。新代次替代尚未完成的旧操作，历史成功操作保留当时结果。

新增管理员接口：服务器操作分页、单条查询和带 expected_retry_revision 的重试。重试返回 202，由队列发布；重试记录与审计同事务，新的 desired revision 防止旧回执完成新尝试，独立重试版本防止旧 worker 消耗新预算。普通重复发布保留“应用失败”，不会将其重置成“等待 agent”。查询不返回内部请求/配置摘要或原始应用错误。权限和 CSRF 沿用管理 API。

心跳与 apply-report 都只在服务器、desired revision、摘要、当前代次精确匹配时完成操作；保存、发布、agent 在线和更大版本均不代表应用成功。配置修改和重试在事务内拒绝已存在的维护任务。完成本节时，维护启动方向的共同目标锁和节点绑定写 API 尚未实现；后续工作见 1.3.10 节。主动降级、清理确认、绑定表单和双端隧道事务仍未完成。

新增测试覆盖真实数据库关闭/重开、失败发布恢复、手动重试恢复、旧删除入口清理恢复、并发幂等请求、审计/回执写入失败的整体回滚、旧 worker 和旧回执拒绝、相关旧入口的代次失效、观测不触发发布，以及 API 权限、CSRF、分页和隐私。

全量 Go 测试、原生与 Linux ARM64 静态检查、store/desired/API/agentproto 并发检查通过；控制端与 agent 的 Linux amd64/arm64 构建通过。无外网 ARM64 systemd 夹具改为实际队列发布，并等待真实 agent 的精确操作回执，随后完整复核双网卡、DNS、流量上报、离线保护、重启、改名、分享暂停/恢复和末节点删除，全部通过。仍使用独立 shadowsocks-rust 客户端，不能据此开放尚未合格的 sing-box SS-2022 outbound。本轮未修改前端。

联调记录过一次 SQLite 写竞争告警。补充真实竞争写事务的定向测试，验证失败入账不推进基线或部分修改分享用量；在计数 epoch 连续时，下一次更大的累计上报补记服务器、节点和分享账本，重复上报不重复收费；普通与 race 测试均通过。这是失败恢复边界的验证，没有消除 SQLite 写竞争或证明任意计数丢失均可恢复。

### 1.3.10 运行条件检查、绑定写 API 与维护互斥基础

工作树新增三个管理员 API：服务器 `network/capabilities`、节点 `network/preview` 和节点 `network` 写入。检查 agent 在线与网络协议、本机配置权限、systemd/nftables、计量和保护诊断、维护状态、锁定及已安装内核、网卡清单新鲜度。控制端预览使用收到清单的时间，不修改原采样时间；agent 本机应用继续使用严格的新鲜状态。

`RequestReadyNodeNetwork` 在保存配置、操作与审计的同一事务中复查条件，预览通过不能绕过保存时变化。专用写入口要求 operation_id、expected_revision 和显式 network；省略 network 报错，null 表示申请清空。接口已丢失时仍可清空，但要求兼容在线 agent、本机允许配置且没有维护任务。完全相同的已接受请求只返回原操作，不能重放旧绑定。

当前准入只开放经过实际会话验证的 sing-box 1.12.14、SS-2022 AES-128 服务端绑定；这不是完整协议能力表。架构准入、其他入口协议、完整影响预览和面板仍待补齐；不能将此 API 的存在描述成 P1b 已发布。

维护任务存在时，控制端保留发布意图、暂停队列及新 desired 获取，等待不消耗发布重试预算。本机新增共享文件锁：配置应用、agent 维护准入和实际维护 worker 共同使用，持久维护状态阻止协调进程重启后穿插配置；只维护控制端不占用 agent 配置目标。

完成本节时，这些定向结果尚未覆盖加入新锁后的完整 systemd 与升级/卸载联调；此前 1.3.9 节全量测试是当时版本的历史证据。该次方案优化只修改文档，没有新增运行时代码。随后继续实施的结果见 1.3.11 节。

### 1.3.11 后台任务锁与正式服务限制下的联调

共同锁进一步覆盖启动时恢复网络保护、心跳修复入口规则和已结算计量资源清理。内核安装和 agent 自动更新运行在后台子进程，可能在主进程返回后继续执行，因此两个 worker 入口各自获取同一配置锁，持有至安装结束。等待有上下文截止时间，每次重试重新检查持久维护状态；不能仅依赖主进程启动 worker 时持有的锁。独立网络监测、正常计数和保护租期续期不获取这把配置锁。

网络夹具改用 `RequestReadyNodeNetwork`，从真实诊断验证准入。持锁期间保存并发布新意图，等待真实 agent 至少两次拉取，核对新操作仍为 waiting_agent、已应用版本未变、两节点 TCP/UDP 与 DNS 仍通过；持续时间超过保护租期，证明旧路径不是仅靠未到期的租期短暂可用。释放后等待新版本的精确回执。另启动真实 core-install 和 agent-update 子进程，持锁时不能进入安装，释放后进入预检并因明确缺少版本或更新参数而退出；该项验证锁边界，不执行下载或替换文件。

网络及维护夹具直接从当前 `install-agent.sh` 提取 agent unit，展开固定安装目录，运行相同的内存/任务数限制、PrivateTmp、ProtectHome 和 NoNewPrivileges。网络夹具仅添加 hold-updates，避免离线环境请求发行更新；没有用最小测试 unit 代替正式限制。这验证 unit 运行条件，不等同于重新执行所有安装器部署路径。

使用当前源码重新构建控制端、agent、验证器和签名工具的 Linux amd64/arm64 本地测试包；包及临时签名源只用于可销毁容器。维护脚本 11 项场景通过，包括非 root 控制端访问固定 root helper、无权用户拒绝、root 权限约束、控制端升级/失败回滚与原数据恢复、校验失败保持旧服务、agent 升级/启动失败回滚，以及 agent 和控制端各自 purge 后的独立回报与另一端保留。

全量 Go 回归、原生与 Linux ARM64 静态检查、store/desired/API/agent/maintenance/agentproto/netinventory 的 race 检查通过。后台锁新增等待截止、释放后接续与取消测试。

最终 ARM64 网络夹具完整通过：上述准入和持锁场景、双节点 TCP/UDP/IPv4/IPv6/DNS、独立分享账本、控制端 503、断卡恢复、agent 停止撤销租期、重启后拒绝不确定的 veth 身份、显式重新绑定、网卡改名、分享暂停/恢复，以及删除最后节点后空计划生效与核心进程停止。实际服务器仍为官方 sing-box 1.12.14，客户端为独立 shadowsocks-rust 1.25.0；这不改变 SS-2022 outbound 未通过的结论。

维护回归与绑定运行回归使用两个独立夹具；本轮没有在同一次真实升级/卸载任务中迁移带绑定的业务。该组合、主动降级/清理确认、AMD64 实际网络运行、真实物理网卡重启和其他入口协议仍需各自验收。未修改前端，没有把本轮结果当作完整 P1b 或 P1–P5 完成。

### 1.3.12 直连出口管理与保存状态

数据库 v17 扩展网络操作类型，新增出口创建、编辑、删除及 `saved` 状态。迁移保留 v16 中的待处理回执、重试版本和重新发布标记。模板保存与业务发布共用操作查询，但含义不同：保存新的出口版本不改变已有节点固定的版本，不推进服务器配置代次，也不等待 agent；被引用出口的启停才进入持久发布队列。后续业务配置不会把历史 `saved` 记录标为已替代。

新增管理员接口：

| 接口 | 当前行为 |
|---|---|
| `GET/POST /api/v1/servers/{id}/egress-profiles` | 列出该服务器出口；创建 direct 模板 |
| `GET /api/v1/egress-profiles/{id}` | 同一数据库快照读取当前版本、引用总数及分页引用；列出节点实际固定的出口版本 |
| `PUT /api/v1/egress-profiles/{id}` | 比较 expected_revision，追加不可变版本，明确提交启用状态 |
| `DELETE /api/v1/egress-profiles/{id}` | 比较版本；有引用时返回 409 与依赖列表，未引用时删除 |
| `GET /api/v1/egress-profiles/{id}/revisions/{revision}` | 读取指定历史版本，用于解释旧绑定 |

所有写入要求 operation_id，并在同一事务内提交配置、操作和审计；创建的 expected_revision 为 0。未知字段、重复 JSON 键、缺少明确启用状态和版本均拒绝。相同请求重传返回原操作，资源删除后仍可查询原接受结果；更改内容或所属服务器不能复用编号。每服务器最多 128 个出口、每出口最多 4096 个版本；操作记录沿用每服务器 4096 条上限，受控归档仍待补齐。

停用允许离线保存，但只返回 `queued`，实际业务状态以 agent 回执为准。恢复被引用出口时，在保存事务内逐个检查节点固定的历史版本，包括暂停节点；最新模板可用不能掩盖旧绑定网卡失效。检查失败或审计写入失败整体回滚，不能部分恢复出口、追加版本或推进发布代次。维护预约期间拒绝新编辑，已接受请求的幂等查询保持可用。

当前仅支持结构化 direct 配置，不包含隧道凭据、端点探测或新协议。该管理 API 尚未接入面板，也未完成全部影响预览；未改变客户端订阅格式。

新增 API 测试通过：严格请求校验、权限与 CSRF、不可变版本、引用分页、依赖删除拒绝、离线停用、实际 desired 中保持旧出口与阻断状态、错误回执拒绝、精确回执完成，以及失败恢复的事务回滚。存储测试增加审计失败时运行状态和发布代次整体回滚，及 v16→v17 迁移保留待处理操作。全量 Go 测试、原生和 Linux ARM64 静态检查、store/desired/API 的 race 检查、控制端和 agent 的 Linux amd64/arm64 构建均通过。本轮未修改前端。

ARM64 systemd 夹具增加真实出口生命周期：先把模板新版本指向另一网卡，旧节点仍走原固定版本；停用后 TCP/UDP 均阻断，另一个节点保持可用；恢复后等待精确回执，再验证原网卡与原出口版本。完整第二轮执行通过锁、出口启停、控制端 503、断卡恢复、agent 停止/重启、显式重绑、改名、分享暂停/恢复及末节点清理。

第一轮在新增出口场景通过后，于控制端 503 阶段的一次服务端先发 TCP 探测出现 EOF。复测通过没有消除该观测；夹具已增加失败前的限量代理日志、保护规则和进程状态输出，避免清理后丢失证据。该异常独立排查，不归并到此前已确定的 sing-box outbound 请求盐时序问题。

独立无外网、无 VpsCT 的对照实验直接连接官方 sing-box 1.12.14 与 shadowsocks-rust 1.25.0，2000 次服务端先发连接中复现 2 次 EOF。对应服务端日志均为 `bad request: missing payload or padding`。核对该客户端的 [固定版本源码](https://github.com/shadowsocks/shadowsocks-rust/blob/v1.25.0/crates/shadowsocks/src/relay/mod.rs#L15)，空载荷时填充长度取 0–900 的闭区间；[SS-2022 规范](https://shadowsocks.org/doc/sip022.html)要求空载荷必须含非零填充，服务端应拒绝两者均为空的请求。因此已确认该测试客户端可产生相同 EOF，但第一轮缺少失败前的代理日志，不能追认其具体原因。

新增可选复现器 `scripts/test-ss2022-interop-container.sh`，由调用者提供已核验的两份官方二进制；使用无外网、无额外能力容器，最多 8 个并发连接、2000 次请求和 190 秒总限制。失败原样返回非零，不重试成成功，不修改生产校验或客户端首包。该复现器没有加入普通回归要求，也不把实验客户端替换为产品内核；后续协议验收需要使用明确通过互操作测试的客户端组合。

整理入库后按上述受限容器方式再次运行，2000 次请求仍复现 2 次相同拒绝（分别为字面量和域名目标），脚本按设计退出 1 并自动清理容器。复现器通过 Linux ARM64 静态检查及 amd64/arm64 构建；这一非零诊断结果没有被计入前述通过的产品回归。

### 1.3.13 出口与节点网络面板

服务器新增“出口”页，提供 direct 模板创建、编辑、启停、未引用删除、分页引用与网络操作记录。模板卡片明确显示“配置：启用/停用”，保存新版本显示“已保存”；运行变更分别展示等待发布、等待应用回执、应用失败、已应用和已被新变更替代。重试携带操作的重试版本，等待新的配置回执，不乐观标记成功。历史已应用结果表示当时收到匹配回执，不是持续的目标可达性证明。

管理员可在已部署节点详情设置监听地址、固定出口版本及独立客户端访问地址，也可显式清除绑定恢复默认。地址选择使用当前接口身份和 `usable_addresses`，缺失的原选择保留并标明不可用，不按同名网卡自动替换。出口新版本不会迁移已有节点。服务器端预检再次核对运行条件；独立访问地址只能填写 IP 或域名，URL、端口和路径在预览阶段即被拒绝。

本轮根据已完成的实际运行证据增加 ARM64 架构准入；未知和 AMD64 暂不能新增绑定，但不妨碍满足清理条件的旧绑定恢复默认。协议仍只开放 SS-2022 AES-128 与锁定的 sing-box 1.12.14。AMD64 和其他入口协议保留在完整交付范围；跨架构构建通过不替代真实会话验证，这些临时限制也不代表完整 P1b 已完成。

表单冻结待提交内容及 operation_id，编辑期间检测版本变化；服务端仍以 CAS 作为最终并发校验。连接中断或 5xx 留下的结果不确定时，保留同一请求供重试，即使后台查询已发现版本前进；核对结果前不能返回编辑并生成新请求。关闭编辑不会撤销已提交操作，应在服务器变更记录中继续核对。不同标签页保存产生的版本变化会阻止旧草稿提交。

### 1.3.14 影响预览与提交复核

节点网络和出口创建、编辑、启停、删除现在先调用只读预览。返回的摘要绑定规范化草稿、继承访问地址、当前依赖和可能重启的节点；保存事务内重新计算并检查运行条件。缺少摘要返回 428，依赖或影响变化返回 409，不保存部分配置。完全相同的已接受请求仍优先返回原操作，响应丢失后复用编号不会再次增加版本。预览不预留操作，也不改变配置。

预览保留暂停/撤销节点的直接引用，并按当前应用驱动列出该服务器所有受管 sing-box 分组可能受影响的节点。创建或只保存出口模板新版本不发布业务配置，原引用继续固定各自版本。恢复出口按每个节点的原固定版本检查，不能拿最新模板替代。节点变更展示监听与客户端访问地址的前后值。

历史清单合并上次完整成功回执以来的保留发布配置，包含部分内核应用失败后可能已经运行的入口。最多读取 64 代、合计 16 MiB；历史被清理、缺失、无匹配成功记录或超出预算时明确提示无法列全旧入口。当前节点和历史入口分别有 2048 项上限；当前清单超过上限直接拒绝预览，历史超过上限保留不完整标记。仅提取名称、协议、端口与分享归属，不返回原始 desired、凭据或诊断错误。清单是配置证据，不是实时运行证明。

2026-09-21 本地隔离浏览器使用真实 API/SQLite 和正式前端、合成 agent 验证：

1. 停用预览显示 1 个直接引用、12 个可能随进程重启的节点及 1 个旧入口，10 项分页可操作；暂停节点正确标记。
2. 预览后新增引用，旧提交被拒绝且出口仍启用；重新预览显示 2 个直接引用和 13 个节点后才可提交。恢复启用保留原固定版本，保存后显示等待应用。
3. 清理旧发布记录后，预览明确提示历史不完整；390×844 下长列表、警告和固定底部按钮可见、可滚动。
4. 不合法 DNS 在预览阶段拒绝。创建出口已提交后模拟一次 502，界面禁用返回编辑，重试只返回原创建结果；未引用出口的删除预览与回执通过。
5. 节点独立访问地址预览显示前后值及全部连带范围，携带摘要提交后网络版本只增加一次。浏览器未记录控制台异常。

全量 Go 测试、store/API/desired race 检查与原生 vet 通过；最终历史去重键调整后相关 store 测试通过。前端类型检查、构建及 17 项前端测试通过，包含最终前端的控制端通过 Linux amd64/arm64 构建。临时浏览器、进程、数据库和夹具源码已清理。本轮未修改 agent 运行流程，未重新运行实际代理网络实验；合成回执不扩大协议或架构验收范围。

### 1.3.15 SOCKS5 出口编译与凭据基础

新增 `networkconfig.SOCKS5` 与 `core.CompileSOCKS5`：上游 IP/域名、端口、认证模式、TCP/UDP、业务地址族/DNS、外层直连绑定/启动 DNS 和有界连接超时。业务 DNS 经对应节点的 SOCKS 出口，启动 DNS 只服务上游解析；每个节点有独立出口、解析器和 socket mark。仅 TCP 时明确拒绝 UDP，并要求 TCP 业务 DNS；不启用 UDP-over-TCP，也不接受任意内核 JSON。

### 1.3.18 SOCKS5 上游域名的启动解析

`ResolveSOCKS5WithDNS` 在应用前通过外层配置中的固定 DNS 地址解析上游，使用指定网卡、源地址和独立节点启动标记。DNS 传输与业务地址族分别校验；UDP 响应截断时只向同一个解析器重试 TCP，不调用系统解析器。控制进程负责连接 socket，无权限 `ctlvps-net` 子进程负责收发和解析 DNS；每个查询有时间和响应大小上限，CNAME 链最多 8 次，同一地址族最多接受 8 个地址。整批应用的启动解析也有时间预算。

候选保留规范化域名及固定 IP，核心只使用已校验的 IP，不再自行解析上游。返回地址中包含被禁止的地址时整组拒绝，本机地址同样不能成为上游。解析结束后重新采集本机接口状态，防止沿用查询前的旧绑定或把新出现的本机地址当成远端。私网 DNS 和上游仍需要尚未接入的独立端点授权，不能借业务私网权限放行。

启动解析使用 `0x44` 标记空间，普通节点业务继续使用 `0x43`。root 创建 socket 后传给无权限子进程，nft 按 socket 所属 UID 拒绝代理自行伪造启动标记；解析收发计入原节点的 RX/TX。配额封禁和未知节点仍丢弃解析流量，待应用的业务租期不因解析成功而自动开放。

### 1.3.19 域名刷新、离线恢复与真实 systemd 中转

域名候选新增解析时间、刷新时间和失效时间。TTL 换算为 30–300 秒的有限寿命（短 TTL 最小按 30 秒），半期开始重新查询；单次失败至少间隔 10 秒重试。相同 IP 的新解析仅更新根权限计划中的期限，不替换静态规则、清空现有租期或重启内核。IP 或绑定发生变化时，先把旧路径置为待应用阻断，再更换核心和保护规则；核心回滚不能重新授予旧路径租期。

本地刷新循环与控制端轮询分别调度，但共享配置互斥和维护锁。HTTP 或安装占用主状态时刷新会推迟，独立网络监测仍继续工作：解析期限届满或时钟退到解析之前时停止续期，内核已有放行最多受原 6 秒租期约束。DNS 查询失败或解析为禁止地址时，相关候选保持阻断，其他有效候选继续应用；共享内核变更仍可能使同组节点短暂重启，不承诺无中断。

agent 将最新已接受的原始中转配置原子保存为状态目录中的 `network-desired.json`，文件为 0600，可能包含运行所需凭据。读取拒绝符号链接、非独占权限、不同服务器、未知代次或不匹配摘要。恢复只接受与持久化最新意图完全一致的配置；新配置部分失败后不能退回旧缓存。每次恢复重新执行本机权限、证书、资源限制和维护检查。快照不包含本机解析结果或私网授权，保存失败会停止相关受管内核。该文件随 agent 数据保留/清理策略处理，不上传为公开诊断。

### 1.3.20 SOCKS5 管理流程与查询调度

管理 API 开放 `socks5` 出口的预览、创建与追加版本，凭据作为独立字段提交。预览摘要与幂等请求同时约束认证信息；预览后更换凭据或复用操作标识提交不同凭据均被拒绝。普通详情、版本、操作和审计不返回用户名/密码，详情仅提供是否配置凭据。省略凭据的编辑保留当前版本，切换无认证后不能隐式恢复更早的凭据；已绑定节点继续固定原版本。

面板在“服务器 → 出口”中提供直连与 SOCKS5 类型，分别设置业务 DNS/地址族，以及连接上游使用的网卡、源地址、地址族和启动 DNS。SOCKS5 默认仅 TCP，关闭 UDP 会把业务 DNS 改为 TCP。编辑已有认证时可保留或重新填写整对凭据；预览只说明认证变更方式，不展示原值或新值。保存出口模板和应用到节点分开确认，节点编辑器能显示固定版本的 SOCKS5 摘要。当前表单说明仅支持非私网、非本机端点，UDP 中继须使用同一上游 IP。

域名查询预算仍为整批 10 秒、单次最多 5 秒；下一批从最后尝试的查询之后继续。预算耗尽后，字面量上游、直连节点及尚未到刷新时间的有效缓存仍能处理。调度顺序不会改变输出节点顺序，避免无意义的核心配置变更；未查询或失败的到期候选保持阻断，不延长旧解析期限。此机制防止持续失败的前序节点永久饿死后面的查询，不承诺任意数量慢上游都能在 TTL 内完成刷新。

### 1.3.21 私网中转窄授权与撤销

新增 root 本机策略 `transport_grants`，同时约束节点、出口、用途、协议、IP/CIDR 和端口。SOCKS5 上游连接与上游启动 DNS 分别授权；UDP 启动 DNS 必须同时具备同端口 TCP 重试授权。允许的地址范围为 RFC1918、CGNAT 和 IPv6 ULA，仍拒绝本机、环回、链路本地和受限转换地址。CIDR 只约束解析候选，实际规则只放行本次固定 IP。UDP 中继端口必须落在本机明确授权的范围，且仍须与上游 IP 相同。

agent 诊断新增独立传输授权能力版本和有界授权观察，用于管理预检；desired、节点远程输入、客户端订阅及恢复快照都不携带本机权限。agent 应用及独立续期监测重新读取 root 策略。授权撤销后停止对应节点续期，已有会话同样受阻断；恢复后按最新已接受配置本地重试。后台恢复现覆盖字面量 SOCKS5，正常字面量节点不因没有 DNS 期限而反复应用。

通用防火墙的私网例外来自已应用的 root 网络计划，保存模板或准备新配置不会提前授予旧进程访问权限。待应用阶段撤下端点例外；通用权限表或绑定表漂移时，在同一 nft 事务中修复两张表并清空健康租期。启动 DNS 使用单独 root socket 标记，普通代理不能借启动 DNS 权限连接私网。

2026-09-21，新增 `NETWORK_SYSTEMD_CASE=socks-private` ARM64 隔离 systemd 实验，使用此前已核验的 sing-box 1.12.14 和 shadowsocks-rust 1.25.0，已通过正式 API 的无授权拒绝、授权上报后的预览与绑定，以及以下实际路径：

1. 私网 SOCKS5、私网启动 DNS 的 UDP 截断回 TCP，TCP/UDP 与 IPv4/IPv6 业务转发；字面量及域名私网业务目标仍被拒绝。
2. 控制端离线时撤销 SOCKS5 授权，已有和新建 TCP/UDP 连接均被阻断，另一节点继续可用；恢复 root 授权后自动重新应用。
3. 缩窄私网 UDP 授权范围后，范围外的实际中继不能转发，独立授权的 TCP 仍可用；恢复范围后 UDP 恢复。
4. 暂停 agent 续期并清空两张表的关键链，独立 watchdog 恢复精确端点规则且保持空租期；恢复监测后才恢复业务。
5. 离线 DNS 在授权网段内换地址、越界答案拒绝和恢复，以及 agent 离线重启、旧 veth 身份阻断与最终空配置清理。公网 SOCKS5 原生命周期用例也回归通过。

全量 Go 测试、相关 race 检查和原生 vet 通过，前端类型检查、构建及 19 项测试通过，Linux amd64/arm64 控制端与 agent 构建通过。面板更新私网授权说明，并在节点编辑器显示授权所需的节点和出口 ID。本轮浏览器对两个本地测试地址均返回 `ERR_BLOCKED_BY_CLIENT`，未完成新增提示的点击验证；临时测试页面、服务和夹具源码已清理。API 与真实 systemd 验证不能替代这项浏览器验收。

操作步骤、授权字段和撤销行为见 [私网中转授权](network-transport-authorization.md)。本轮私网外层实际会话覆盖 IPv4；ULA 外层、其他入口/架构、特殊 UDP 响应和完整发布矩阵继续列为未完成项，不将字段或交叉构建通过视为运行验收。

### 1.3.23 固定转发资源、端口和下发基础

新增独立 `PortForward`/`ForwardSpec`，结构化保存监听、固定目标、显式来源模式、连接预算、UDP 超时和不可变出口引用。空 CIDR 集合保持拒绝，不能把缺省来源解释成任意来源。转发不写入节点库，也没有分享或客户端凭据字段。公共 `ResourceIdentity` 与直连出口编译器保留原节点 `0x43` 标记，转发使用独立 `0x45` 标记和 resolver/tag。

数据库 v20 增加共享监听端口预留、转发及不可变版本。新节点与转发互相检查数字端口；既有重复节点预留逐条迁移，不删掉旧所有者。转发更换监听端口时保留新旧预留，删除先进入退役状态，只有后续准确清理回执才能释放；本轮尚未实现清理确认处理器。出口必须属于同一服务器，目前仅接 direct，不跟随出口模板的最新版本；停用及退役资源仍保留引用。内核版本修改检查也包含转发。

`RequestPortForward` 是尚未接 HTTP 的持久化原语。变更、端口、版本、服务端发布代次、幂等操作记录和审计在一个事务中提交；保存状态为 queued，不能冒充应用成功。出口启停、节点共享进程重启的影响计算现包含当前转发及历史发布中的旧监听，出口依赖查询也显示独立转发引用。

desired 新增可选 `forwards` 与独立 `network_forward_version`，省略时保留旧 wire/hash。控制端按每次请求的能力 header 下发，即使返回空清理配置或条件请求也不绕过校验；能力要求在最后资源删除后保留。当前 agent **尚不宣告此能力，且明确拒绝执行含转发的配置**，直到共享 guard、应用事务、计量与清理链路接齐；因此本阶段不是可用转发功能交付，也未开放管理表单。

必要验证覆盖同端口互斥、旧端口保留、版本 CAS、跨服务器出口拒绝、固定引用、退役不可复活、审计失败整事务回滚、幂等请求、旧数据迁移、影响历史和 HTTP 下发版本协商；相关 Go 包测试通过。未重复前一节的网络容器实验，未修改前端或连接真实 VPS。

### 1.3.24 固定 TCP 转发编译、保护和独立计量

共享配置编译器和 sing-box 驱动增加显式转发集合，转发不伪装成节点，也不继承节点的业务私网权限。agent 的绑定准备事务已改为按资源类型和 ID 区分，先安装阻断，再解析本机网卡，只有成功应用对应内核后才激活候选；尚未接入主应用函数。当前运行候选只接受公网字面量 TCP 目标，域名、私网目标及 UDP 仍明确拒绝。

生产 network guard 支持独立 forward 租期、每包来源检查、固定目标/端口限制和本机目标拒绝。连接上限放在独立的稳定准入链中，普通租期或保护规则更新不清空已有连接占用。root 策略记录准入规则摘要；准入状态丢失或连接上限变更时先停用共享 public 进程，恢复后等待应用确认，不能直接遗忘旧连接并重新放行。这部分 root 恢复和完整 systemd 应用联调仍待验收。

### 1.3.26 SSH 客户端与服务器出口

客户端节点支持手动结构化编辑、mihomo YAML 导入、mihomo 与 sing-box 配置导出。密码与内联私钥二选一，必须明确用户名及可信主机公钥；拒绝文件路径、空主机公钥、跳过校验、UDP 和未知参数。SSH 特有多行私钥不会放宽其他协议的参数检查。认证信息属于客户端节点时会进入该节点订阅，不生成自创的通用 URI。

已通过客户端导入/输出、主机公钥和参数限制、服务端凭据加密/保留/固定引用及清理后兼容要求的定向测试。官方 sing-box 1.12.14 在无网络容器中通过密码、内联私钥连接和错误主机公钥拒绝。完整 ARM64 agent/systemd SSH 中转实验已通过管理 API 创建/绑定、指定 WAN、隧道内 TCP DNS、分享流量归属、UDP 拒绝和出口停用后无直连回退。首次定位隔离 HTTP helper 漏传 SSH 能力声明，修复后同一场景通过。尚未把所有架构、入口协议、私网及域名组合标记为已验收。

### 1.3.29 WireGuard 单用户接入、接口归档与分享继承

接口历史新增按稳定 ID 分页和归档接口。仅消失的接口可归档，保留原始身份、基线和账本，重新出现自动取消归档；容量上限不因归档而被绕过。分享目标可保存网络模板，在新建专属入口时复制监听和固定出口版本，既有入口、重签和恢复不随模板修改。当前继承遵循已开放的入口能力及其驱动限制；WireGuard 私钥不能作为共享模板复用，应逐节点建立 Peer。

### 1.3.30 托管 WireGuard 双端流程

新增托管中转记录、预览/创建/退役 API 和服务器出口页。创建为入口与落地分别生成独立身份；落地使用隐藏传输资源，不可从普通节点 API、IncludeAll 或手动节点选择进入订阅。落地计数复用受管计量身份及终值结算，但写入独立 transit 账本，不再次扣入口分享配额。

流程持久化为等待落地、等待入口、已应用、等待入口阻断、等待落地撤销、已退役。阶段推进在事务中核对精确的最新 desired revision/hash、已发布代次及维护互斥；重启继续处理原记录。退役后入口保留停用的出口引用，显式解除绑定才恢复默认路径。操作编号严格幂等，活跃两端禁止直接删除服务器。托管出口不能通过普通出口编辑器改写。

当前支持已有 SS-2022 AES-128 入口到另一台托管 VPS，复用既有 ARM64/1.12.14 准入。双端状态机、幂等、资源隐藏、计量隔离、退役顺序和没有精确回执时禁止推进的定向测试通过。两个独立 systemd 容器、两个真实 agent 的完整场景已通过公网字面 IP、TCP/UDP、服务端先发、两端独立账本、控制端 worker 重建、持久退役、最终计量 ACK 和落地端口释放；无直连回退。落地账本的保留不等于立即删除所有历史加密凭据。私网与域名地址的后续准入见 1.3.33。表单已在隔离本机面板点击确认。

### 1.3.32 独立内核监听与 VLESS Reality 绑定

Snell 5.0.1、mita 3.37.0 已接入指定监听 IP、独立 cgroup 租期保护、按实际内核版本预检、版本设置互斥及分享新入口继承。独立内核暂不支持指定业务出口；界面明确保持宿主机路由。sing-box 版本变更不会误伤只绑定 Snell/mita 的服务器。

ARM64 真实 systemd 检查主体通过指定监听与其他 IP 拒绝、mieru TCP/UDP 业务、接口改名后保持身份并重新收敛、断卡阻断。Snell 只检查实际服务监听与保护，不声称已使用 Surge 完成认证会话。该次命令因运行期间编辑 shell 脚本，主体通过后退出 127；保留此边界，未重复完整业务矩阵。之后独立 Reality 脚本以零退出通过。

VLESS Reality 已通过官方 sing-box 1.12.14 的实际认证链路、指定监听与出口、TCP/UDP、服务端先发、IPv4/IPv6、域名业务及断卡阻断。连同此前 Trojan、AnyTLS、Hysteria2、TUIC 的实际 direct 绑定结果，已开放这些入口的监听/直连绑定。它们经 SOCKS5/SSH/WireGuard 出口的组合仍未开放，不能把 direct 验证扩大解释成全部出口组合。

### 1.3.33 托管落地的域名与私网地址

托管 WireGuard 可选落地服务器已配置的域名、agent 报告的公网地址或本机接口地址。创建私网落地时先分配入口节点与出口身份，出口保持停用；root 独立授权完成前不能推进到入口应用。阶段推进重新检查最新接口、授权与能力，落地成功回执不能跳过入口条件。面板显示所需身份及未满足的入口检查。

定向存储测试通过公网、域名、私网无授权拒绝推进、授权后启用及完整退役。真实双 agent 实验仍只覆盖公网字面地址；没有为域名/私网重新跑双端完整矩阵。2026-09-23 已在本机隔离面板点击核对新地址字段和授权提示。

### 1.3.34 固定 TCP 转发域名解析

域名目标使用所选直连出口的 DNS，查询 socket 绑定对应接口/源地址，使用独立 `0x46` 标记并计入该转发账本。agent 校验每个答案，固定本次 IP 后再编译，核心不自由解析。DNS 期限、接口变化、目标改变均参与本机保护；解析失败或到期时阻断，使用最新已接受配置本地重试。旧 agent 缺少解析能力时管理预检拒绝启用。

必要组件测试和 pin 到期/变址测试通过。实际 ARM64 agent/systemd 场景通过管理 API、指定 WAN、独立用量、DNS 私网重绑定阻断、返回公网后恢复、监听端口修改及最终退役结算。首次失败来自 desired 的旧字面量校验，已修复；第二次夹具读错错误字段，实际服务已因私网答案停止，改为核对正常 apply_error 后同一场景以零退出通过。未删除阻断断言或放宽生产规则。

### 1.3.35 私网固定转发与本次收尾

固定 TCP 目标新增 `forward_grants` 本机授权，与节点 `private_nodes`、`transport_grants` 完全分开。授权匹配转发 ID、出口 ID、私网地址范围和固定 TCP 端口；创建时可停用保存，获得 ID 后由 root 配置，agent 上报后再启用。域名的每个私网答案都必须匹配；实际例外只放行固定 IP/端口，不能直通整个私网网段。授权撤销停止续期并重新应用，恢复授权后可本地重试。固定转发的启动 DNS 当前仍只接受公网地址。

组件检查及“停用保存→缺权拒绝→匹配授权→提交前撤权拒绝”测试通过。ARM64 真实 systemd 场景以零退出通过受控私网域名、目标可达对照、指定 WAN、独立账本、授权撤销阻断、恢复、监听修改及退役结算。没有把节点授权扩大成转发权限。

独立监听、域名转发和私网转发新增本机持久能力要求，签名验证后的候选程序必须声明对应能力；删除资源后仍保留要求，安装器、自更新及维护 worker 共用检查。降级检查的定向测试通过。前端补充私网操作步骤和应用失败提示，最新 typecheck/build 已通过。

架构准入调整为项目已有的 Linux AMD64/ARM64 发行架构，两者使用相同 Linux 网络逻辑，并均检查最新网卡、内核版本、systemd、nftables、本机策略和计量状态。此调整承认“支持范围”与“已执行的运行验证范围”有区别；未知架构仍拒绝，新测试确认 AMD64 也不能跳过宿主机条件。实际容器证据仍仅覆盖 ARM64。

收尾已通过最新前端 typecheck/build、Linux amd64/arm64 控制端与 agent 四项构建、diff 空白及 shell 语法检查。本机浏览器已核对域名/私网目标表单、停用保存开关和托管落地授权说明；临时浏览器、面板进程和测试数据库已清理。新增检查只覆盖变更和失败路径，未重复全量 Go/race 或全部协议矩阵。

### 1.3.36 固定 TCP 转发经传输出口

固定 TCP 转发已支持选择 SOCKS5、SSH、WireGuard 出口，保存时固定出口配置及凭据版本，不能因后续模板编辑而静默变更。转发编译使用独立资源身份、标记、路由和计量；外层连接绑定指定网卡及来源地址，租期只允许通往已固定的上游端点。上游端点必须是公网 IP 字面量，目标必须是 IP 字面量，二者分别检查地址族、授权与变更。经隧道传输时，本机保护不为业务目标放开直连路径，出口或上游失效即阻断。私网业务目标仍需该转发自己的 `forward_grants`，不复用节点或传输授权。

协议字段、存储快照、desired、agent 本机校验、能力协商和已签名候选程序的降级检查均已接入。已保存的传输出口转发即使退役，也保留 agent 能力要求。前端提供相应出口选择及固定 IP 限制说明。定向 Go 测试和前端 typecheck/build 通过；ARM64 官方 sing-box 1.12.14 的隔离 systemd 场景分别以零退出通过 SOCKS5、SSH 和 WireGuard 的创建、预检、应用、流量、修改和退役。SSH 首轮在全部步骤 PASS 后因运行期间脚本被编辑而退出 127；稳定脚本的单场景重跑以零退出通过，没有重复完整矩阵。三者未扩展到 UDP。

### 1.3.37 官方内核适配与功能边界

按用户要求撤回自编译内核方案：删除两处补丁、构建脚本、内核附件打包、控制端内核下载 API 与 agent 的控制端内核下载例外。原有安装/卸载与网络资源的其他改动保留。发行包只含 VpsCT 自身组件，sing-box 沿固定官方 Release 通道安装。

版本策略集中在 `internal/corecompat`。普通网络绑定支持 1.12.14 起的 1.12.x、1.13.x、1.14.x 官方稳定系列；SS-2022 出口要求 1.14.1 起的 1.14.x。支持兼容系列内的补丁升级，拒绝带自定义后缀的版本和未知新系列绑定；保留旧默认值与管理员已经选定的版本。存在 SS-2022 依赖时，设置事务拒绝降级到不支持该功能的系列。

官方 1.14 配置使用 `certificate_provider` 替代内嵌 `tls.acme`，移除已无需设置的 `independent_cache`；旧系列继续生成原格式。依据 [官方迁移说明](https://sing-box.sagernet.org/migration/)。测试夹具记录真实官方版本，不再把旧二进制标记为修改版。

本轮下载官方 1.14.1 Linux ARM64 发行归档，SHA-256 与 GitHub 官方 Release 元数据一致。在无外网 Ubuntu 容器中完成 2,000 次 SS-2022 早期响应连接（字面量和由夹具提供解析的域名），零失败；真实双 agent/systemd 托管 SS-2022 完成 TCP/UDP、服务端先发、独立账本、重启续办、顺序退役、最终计量清理、端口释放和不回退直连。这里不宣称上游已经彻底修复所有旧版时序问题。Trojan、AnyTLS、Hysteria2、TUIC 的正式 agent/systemd 监听与直连出口测试通过 TCP/UDP、服务端先发、IPv4/IPv6、域名和断卡阻断；官方二进制的 ACME 新配置语法检查通过。TCP 固定转发的实际 API 预览/创建/重试、agent 应用、指定出口、独立流量、改端口、退役结算及端口释放亦以零退出通过。

官方 1.14.1 固定转发实验的 TCP/UDP 基本收发、IPv4/IPv6、指定出口、来源限制、独立计量与撤销通过，但 TCP 半关闭和 UDP 空闲映射回收未通过，实验仍以非零退出记录失败。UDP/TCP+UDP 固定转发因此在管理预检、desired、agent 校验和编译层阻止启用；旧记录保留，发布阻断配置，仍允许停用、删除或转换 TCP。普通节点及托管中转的 UDP 不受此限制。TCP 半关闭限制在页面和运维文档说明，不通过修补内核规避。

全量 Go 回归、`go vet ./...`、前端测试/typecheck/build、安装/卸载参数检查通过，Linux AMD64/ARM64 的控制端和 agent 编译通过。浏览器确认固定转发的 UDP/TCP+UDP 选项禁用且说明可见。全量回归发现既有 nft 测试仍只接受节点 DNS 标记，已按现有节点/转发双标记更新精确断言，保留 root UID 检查与默认拒绝验证。

新版官方默认 Linux 包依赖 glibc，隔离夹具已使用 Ubuntu。AMD64 实际网络、其他系统运行库及复杂拓扑的完整矩阵仍待验证。
