# 1. 私网中转与固定转发授权

本说明适用于多网卡与中转开发版本，运行验收范围见 [实施进度](network-implementation.md)。它连接已有 SOCKS5 服务，不负责创建运营商专线。入口协议和架构仍须满足面板中的运行条件。

## 1.1 配置顺序

1. 在“服务器 → 节点线路 → 高级工具 → 自定义出站线路”保存 SOCKS5 出站规则，填写上游、认证、外层网卡和业务 DNS。规则可以先保存，此时不会开始转发。
2. 在节点的“服务器网络”选择该出口。编辑器显示本机授权需要的节点 ID 和出口 ID。
3. 如果上游或启动 DNS 是私网地址，由该 VPS 的 root 管理员在 `/etc/ctlvps/security.json` 中增加对应 `transport_grants`。保留原文件中的其他安全策略；不要用本文示例覆盖整份文件。
4. 等待 agent 上报新诊断，再预览和提交节点绑定。预览会拒绝缺失或不匹配的授权。提交后须等对应操作显示服务器已应用；保存模板、预览通过都不等于已经生效。

本机安全策略文件及其父目录必须由 root 拥有，且不可被组或其他用户修改。建议先在同目录准备完整新文件、检查 JSON 和所有原有字段，再以 root 原子替换。不要为了连接一个端点将节点加入 `private_nodes`：该字段代表业务访问私网的另一种权限。

## 1.2 授权字段

以下是应合并到现有策略中的字段示例。ID、地址和端口仅为虚构示例，必须换成实际绑定和受信任服务的范围。

```json
{
  "transport_grants": [
    {"node_id": 11, "egress_profile_id": 7, "purpose": "socks5", "network": "tcp", "address": "10.23.0.2", "port": 1080},
    {"node_id": 11, "egress_profile_id": 7, "purpose": "socks5", "network": "udp", "address": "10.23.0.2", "port": 40000, "port_end": 60000},
    {"node_id": 11, "egress_profile_id": 7, "purpose": "bootstrap_dns", "network": "tcp", "address": "10.23.0.53", "port": 53},
    {"node_id": 11, "egress_profile_id": 7, "purpose": "bootstrap_dns", "network": "udp", "address": "10.23.0.53", "port": 53}
  ]
}
```

| 字段 | 含义 |
|---|---|
| `node_id`、`egress_profile_id` | 两者必须同时匹配；另一节点不能借用同一出口的授权 |
| `purpose` | `socks5` 用于连接上游；`bootstrap_dns` 仅用于解析上游域名 |
| `network` | `tcp` 与 `udp` 分别授权 |
| `address` | 规范 IP 或已掩码的 CIDR；可使用 RFC1918、CGNAT、IPv6 ULA 范围 |
| `port`、`port_end` | 包含两端的端口范围；省略 `port_end` 表示一个端口；DNS 只允许单端口 |

每台服务器最多 1024 条，同一节点和出口最多 16 条，完全重复条目会被拒绝。CIDR 只用于约束候选端点，实际防火墙仅放行本次选定的一个 IP 和对应端口，不放行整个网段。

仅 TCP 的上游不需要 SOCKS UDP 授权。启用 UDP 时，上游选择的实际 UDP 中继端口必须落入授权范围，且中继必须使用同一个上游 IP。端口范围需依据上游的真实配置；未知时不要照抄示例范围。当前跨 IP 中继和零地址中继响应的兼容性仍未验收。

上游使用字面量 IP 时无需启动 DNS。上游是域名、启动 DNS 为私网时，TCP 查询需 TCP 授权；UDP 查询需同时授权 UDP 和同端口的 TCP 截断重试。公网启动 DNS 不需要私网授权。业务 DNS 经 SOCKS5 转发，其配置不会获得启动 DNS 的本机直连权限。

## 1.3 生效、撤销与恢复

授权按节点和出口 ID 绑定，不跟随出口的最新版本自动变更节点配置。凭据轮换可以复用相同端点范围，但换 IP、端口或出口 ID 时必须重新满足授权。域名解析的每个候选都会检查范围；包含不允许地址的结果不会进入核心。

agent 应用时重新读取 root 策略和网卡状态，控制端诊断只用于预检。SOCKS5 授权、启动 DNS 授权与业务访问私网权限相互独立。本机地址、环回、链路本地、元数据及受限转换地址不能因私网授权变成可用上游。

独立监测发现已应用的 SOCKS5 授权被撤销或改窄后停止续期，已有连接也受阻断；原有防火墙租期最多 6 秒。恢复授权后，可根据最新已接受配置在控制端离线时重试。域名和字面量端点都纳入恢复；缓存中的旧授权不作为依据。共享核心重配置可能使同组节点短暂重启。

本机策略无效、配置暂停、网卡身份无法确认或维护占用时，不承诺自动恢复。应先修复相应条件，不要通过放宽整个私网权限消除错误。虚拟接口在 agent 重启后无法证明身份连续性时，仍须明确重新绑定。

## 1.4 已验证范围

ARM64、sing-box 1.12.14、SS-2022 AES-128 入站、独立 shadowsocks-rust 1.25.0 客户端的隔离 systemd 实验已验证私网 SOCKS5、私网启动 DNS、TCP/UDP、IPv4/IPv6 业务、拒绝私网业务目标、撤销已有连接、离线恢复及防火墙修复。私网外层实际会话目前覆盖 IPv4；IPv6 ULA 的授权和地址检查有单元测试，外层实际会话仍待验证。不能据此宣称所有架构、入口协议或 SOCKS5 服务端都已兼容。

## 1.5 SSH 外部出口授权

SSH 出口复用接口选择、受限 DNS、租期与离线恢复流程，但使用独立传输用途 `ssh`。私网上游必须按实际节点 ID、出口 ID、目标地址和固定 TCP 端口授权；不接受 UDP 或端口范围。SOCKS5 授权不能用于 SSH，业务私网权限也不能代替传输授权。公网 SSH 上游不需要私网例外，仍拒绝本机、环回和受限地址。

在面板「服务器 → 节点线路 → 高级工具 → 自定义出站线路」创建 SSH 出站规则，提供专用转发账号、密码或内联私钥，以及经可信渠道确认的主机公钥；再在支持的已部署节点中选择该出口和固定版本。不会部署 SSH 服务、读取本机密钥文件或复用 VPS 管理凭据。SSH 只支持 TCP，业务 DNS 必须使用 TCP。客户端订阅只保留入口节点参数，不包含服务器中转密钥。

## 1.6 WireGuard 与托管 VPS 中转

外部 WireGuard 的私网端点使用 `purpose: "wireguard"`、`network: "udp"`，授权固定端口，不接受端口范围。节点和出口 ID 必须匹配。该授权只允许 WireGuard 外层端点，不授予隧道内业务任意私网权限。使用域名时，私网启动 DNS 仍需单独的 `bootstrap_dns` 授权。

托管中转创建后，面板显示入口节点 ID 和自动生成的出口 ID。入口 VPS 的 root 按两者及落地 IP/端口配置授权。落地端已应用后，入口仍等待本机条件满足才启用；可以从两端状态及失败检查定位原因。退役先阻断入口，再撤销落地 Peer 并完成最终计量。域名必须是落地服务器已配置的名称，私网 IP 必须由落地 agent 上报。

## 1.7 固定 TCP 转发

固定转发使用独立 `forward_grants` 字段。它不接受 `private_nodes` 或节点的 `transport_grants`，即使节点与转发的数字 ID 相同，也不能借用授权。

1. 在「服务器 → 节点线路 → 高级工具 → 固定端口映射」填写目标 IP/域名、TCP 端口和来源限制，关闭“启用转发”并保存。
2. 记下列表中的转发 ID 及出口 ID；“按宿主机路由”的出口 ID 为 `0`。
3. 由入口 VPS 的 root 将下列字段合并到原有 `/etc/ctlvps/security.json`，保留其他全部配置。示例身份与地址均为虚构值。
4. 等待 agent 上报，再编辑转发并启用。授权撤销或不匹配时停止租期，已有连接也受阻断；恢复后根据最新已接受配置重试。

```json
{
  "forward_grants": [
    {"forward_id": 12, "egress_profile_id": 7, "address": "10.42.0.10", "port": 443}
  ]
}
```

仅支持固定 TCP 端口，地址可为规范的 RFC1918、CGNAT 或 ULA 地址/网段；每台服务器最多 1024 条、每个转发最多 16 条。域名每次解析都检查全部答案，实际防火墙只允许本次固定 IP 与端口。本机、环回、链路本地及受限转换地址始终拒绝。使用域名须选择直连出口，固定转发的启动 DNS 当前须为公网地址；隔离私网可直接填写目标 IP。

私网转发的 ARM64 实际场景已验证受控域名解析、独立授权、撤销阻断、恢复、监听变更、账本结算与退役释放；未把这些结果扩展为全部网络或架构的运行验收。
