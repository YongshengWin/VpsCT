# 网络与中转使用指南

[返回 README](../README.md) · [安装与运维](operations.md) · [节点与订阅](subscriptions.md)

本文按操作流程说明当前源码中的网络功能。正式安装是否包含这些功能，应对照 [变更记录](../CHANGELOG.md)；开发过程与实验结果见 [实施记录](network-implementation.md)，计划见 [设计方案](network-and-tunnel-design.md)。

## 1. 先确定要改变什么

| 需求 | 入口 | 作用 |
|---|---|---|
| 查看网卡与流量 | 服务器 → 节点线路 → 看网卡和流量 | 查看各接口状态、地址、速率与历史 |
| 选择服务器配额统计接口 | 看网卡和流量中的计费设置 | 改变服务器用量来源，不改变业务路由 |
| 指定节点监听或出站 | 已部署节点 → 网络设置 | 分别设置监听地址、出口版本与客户端访问地址 |
| 经另一台受管 VPS 出网 | 服务器 → 节点线路 → 添加中转 | 自动协调入口与落地两端配置 |
| 使用外部代理或自定义直连 | 节点线路 → 连接已有代理 | 创建供节点固定引用的出口规则 |
| 固定端口映射 | 节点线路 → 转发固定端口 | 建立独立的 TCP 固定目标转发 |

出站网卡决定业务从哪里发出，计费网卡决定服务器配额统计什么，监听地址决定服务在本机哪里接收连接，客户端访问地址决定订阅里写什么。只指定源 IP 不保证改变宿主机路由。操作不会替你配置云安全组、宿主机地址或公网 DNS。

## 2. 网络观测与计费

### 2.1 网卡状态和历史

页面展示接口类型、地址、链路状态、默认路由、RX/TX、实时速率与历史。回环、网桥和 veth 可切换显示。离线或采集失败时保留历史状态，不用零流量伪装实时数据。

接口按稳定身份跟踪：改名保留身份；删除重建即使名称或 ifindex 相同，也不能继承原绑定。设备累计值与面板按基线计算的周期用量不同。计数倒退或观测中断会重新建基线。

消失的接口可以归档，原身份、基线与账本保留；重新出现后自动取消归档。归档不删除历史，也不绕过接口数量限制。

### 2.2 切换服务器计费接口

1. 确认 agent 在线、支持网络能力，并已上报完整的新鲜接口清单。
2. 选择 1–16 张计费接口，查看拓扑重叠、缺失接口等预检结果。
3. 预览切换并提交，等待 agent 确认。保存成功不等于新策略已生效。
4. 查看应用状态和后续用量，异常时根据缺卡或策略不匹配提示处理。

切换使用同一份快照结算旧来源并建立新基线，冻结批次与回执支持重试去重。缺卡、拓扑重叠或旧策略上报时不会悄悄切换到其他接口。服务器配额仍按入站加出站计算；节点、分享、固定转发各有自己的账本，不把它们重复相加作为服务器配额。

## 3. 节点监听与自定义出口

### 3.1 创建并绑定出口

1. 在“连接已有代理”中创建 direct、SOCKS5、SS-2022、SSH 或 WireGuard 规则。
2. 按需填写外层网卡、源地址、地址族和 DNS；认证字段按协议填写，SSH 必须校验主机公钥。
3. 在已部署节点的网络设置中选择监听地址、出口固定版本与客户端访问方式。
4. 查看影响预览，确认相关节点与共享进程重启范围后提交。
5. 等待匹配当前配置的应用回执，再用客户端验证实际连接。

出口内容按版本保存，修改模板或轮换凭据不会让已有节点自动追随新版本。编辑时可保留已有凭据；需要切换的节点须显式引用新版本。停用、删除和重新绑定会检查依赖；预览后依赖改变，需要重新预览。

监听地址须属于目标服务器的可用地址。客户端访问地址可继承服务器公网地址或单独指定；显式指定的地址不随服务器公网地址变动。恢复默认网络需要显式操作。

### 3.2 协议与运行条件

| 类型 | 适用范围与限制 |
|---|---|
| direct | 指定网卡、源地址、DNS 与地址族，保留宿主机路由语义 |
| SOCKS5 | 支持认证与可选 UDP；关闭 UDP 时业务 DNS 使用 TCP；特殊 UDP 中继兼容仍需核验 |
| SS-2022 | 使用适配的官方 sing-box；所需版本及升级步骤见运维文档 |
| SSH | 密码或内联私钥认证，必须固定主机公钥；仅 TCP，业务 DNS 使用隧道内 TCP |
| WireGuard | 配置 Peer、密钥、地址与 MTU；不是宿主机整机 VPN |
| Snell / mita | 支持指定监听地址，业务出站沿用宿主机路由，暂不支持绑定传输出口 |

内核、agent 能力、架构与本机条件都须通过预检。兼容版本和升级确认统一见 [内核版本与升级确认](operations.md#47-内核版本与升级确认)。配置兼容范围不等于所有协议组合和架构均已完成运行测试。

### 3.3 DNS、私网和故障处理

域名上游使用受限启动解析与到期刷新；相同 IP 续期不重启内核，地址变化先阻断旧路径再重新应用。控制端暂时离线时，agent 可按持久化的最新配置继续刷新和恢复，但恢复仍核对本机策略。

私网上游或固定转发目标必须在对应 VPS 本机进行窄授权，步骤见 [私网传输授权](network-transport-authorization.md)。节点的业务私网访问开关不能代替传输端点授权。

接口丢失、身份改变、地址失效、解析不安全或保护规则异常时，相关路径保持阻断，不回退直连；无关节点不应因此改变出口。先修复本机网络或授权，再检查最新配置回执，必要时从操作记录重试。不要通过手工放宽防火墙绕过预检。

## 4. 托管双端中转

1. 在入口服务器选择「添加中转」，选择入口节点和落地 VPS。
2. 选择 WireGuard 或 SS-2022；需要时展开高级设置，配置连接地址、网卡和 DNS。
3. 预览并确认两端影响。落地端先创建独立服务，入口在落地端确认应用前保持阻断。
4. 等待两端最新配置回执，随后验证客户端流量确实从落地端发出。
5. 不再使用时退役线路；系统先阻断入口，再撤销落地服务并结算最终流量。

任务持久化，可在进程重启后续办。活跃中转的两端不能直接删除服务器，托管出口也不能通过普通出口编辑器改写。域名或私网连接地址仍遵守解析与本机授权规则。

退役后入口保留停用出口引用，显式解除绑定才恢复默认路径。已退役线路可从常用列表移除，并通过“显示已移除记录”查看；历史流量与计量身份保留。

## 5. 固定 TCP 端口映射

### 5.1 创建和修改

固定转发是独立资源，不是代理节点。配置监听端口、固定目标、允许来源、连接预算与出站规则，预览后提交并等待应用。直连支持 IP 或域名目标；经 SOCKS5、SSH、WireGuard 等已适配传输出口时，当前要求固定 IP 目标，具体组合以预检结果为准。

转发独立计量。修改端口时旧端口继续预留到清理确认；删除先退役，agent 持久化最终计量和清理收据，控制端结算去重并确认后才释放端口与本地状态。不能把“已保存”当成端口已释放。

### 5.2 明确限制

目前仅开放 TCP。官方内核的 UDP 空闲映射回收未通过验证，UDP/TCP+UDP 固定转发在预检、下发和应用层均阻止启用。旧记录保留，可停用、删除或改为 TCP；新阻断配置应用后旧 UDP 监听才撤下。代理节点和托管中转的 UDP 不受此限制。

官方 sing-box 1.14.1 的 TCP 半关闭测试未通过。依赖发送 EOF 后继续接收响应的应用须单独验证。VpsCT 不通过修改或自行编译内核绕过这些限制。

## 6. 验证范围与后续能力

当前实际网络验证主要覆盖 Linux ARM64 隔离环境；AMD64 交叉编译通过不能代替实际流量验收。其他入口与出口组合、ULA 外层、复杂 NAT/MTU、物理网卡跨重启、原生 WireGuard 客户端以及携带网络资源的升级卸载仍有缺口。

Snell/mita 隧道出站、整机 VPN、任意多跳、自动故障切换和带宽叠加属于后续扩展。详细实验按日期保留在 [实施记录](network-implementation.md)，正式发布验收见 [发布流程](releasing.md)。
