# 网络与中转使用指南

当前发行仅支持 Linux AMD64（x86_64），ARM 支持暂停；下文 ARM 测试结果仅为历史记录，不构成当前兼容承诺。恢复支持需要真实测试机器完成验证。

[返回 README](../README.md) · [安装与运维](operations.md) · [节点与订阅](subscriptions.md)

本文按操作流程说明当前源码中的网络功能。正式安装是否包含这些功能，应对照 [变更记录](../CHANGELOG.md)；开发过程与实验结果见 [实施记录](network-implementation.md)，计划见 [设计方案](network-and-tunnel-design.md)。

## 1. 先确定要改变什么

| 需求 | 入口 | 作用 |
|---|---|---|
| 查看网卡与流量 | 服务器 → 网卡与流量 | 查看各接口状态、地址、速率与历史 |
| 选择服务器配额统计接口 | 网卡与流量中的计费设置 | 改变服务器用量来源，不改变业务路由 |
| 指定节点监听或出站 | 已部署节点 → 网络设置 | 分别设置监听地址、出口版本与客户端访问地址 |
| 入口 → 落地，可选中转 | 服务器 → 节点线路 → 转发线路 → 创建线路 | 选择入口和落地节点，可增加中转；自动编排一段或两段转发并生成独立订阅 |
| 经另一台受管 VPS 出网 | 服务器 → 节点线路 → 节点出口 → 出口方式 → 另一台受管 VPS | 自动协调入口与落地两端配置 |
| 使用外部代理或自定义直连 | 节点线路 → 节点出口 → 出口方式 → 已有代理或本机网卡 | 同页配置出口，再选择节点绑定应用 |
| 固定端口映射 | 节点线路 → 单段转发 | 建立独立的 TCP、UDP 或 TCP+UDP 固定目标转发 |

服务器详情主导航直接提供“网卡与流量”。节点线路页使用固定侧边导航，包含转发线路、节点出口、单段转发和变更记录；节点出口的来源通过“出口方式”表单选择，不再叠加子级标签页或折叠入口。自动编排生成的转发规则与出口由对应线路维护，不在手动配置列表重复展示。节点选择器提供协议、来源、服务器快捷筛选，可与关键词搜索叠加；清除筛选不会修改已选节点。

出站网卡决定业务从哪里发出，计费网卡决定服务器配额统计什么，监听地址决定服务在本机哪里接收连接，客户端访问地址决定订阅里写什么。只指定源 IP 不保证改变宿主机路由。操作不会替你配置云安全组、宿主机地址或公网 DNS。

## 2. 网络观测与计费

### 2.1 网卡状态和历史

页面展示接口类型、地址、链路状态、默认路由、RX/TX、实时速率与历史。回环、网桥和 veth 可切换显示。离线或采集失败时保留历史状态，不用零流量伪装实时数据。

接口按稳定身份跟踪：改名保留身份；删除重建即使名称或 ifindex 相同，也不能继承原绑定。设备累计值与面板按基线计算的周期用量不同。计数倒退或观测中断会重新建基线。

消失的接口可以归档，原身份、基线与账本保留；重新出现后自动取消归档。归档不删除历史，也不绕过接口数量限制。

### 2.2 切换服务器计费接口

1. 确认 agent 在线、支持网络能力，并已上报完整的新鲜接口清单。
2. 选择 1–16 张计费接口，查看拓扑重叠、缺失接口等预检结果。
3. 预览切换并提交，等待 agent 确认。保存成功不等于新策略已生效。
4. 查看应用状态和后续用量，异常时根据缺卡或策略不匹配提示处理。

切换使用同一份快照结算旧来源并建立新基线，冻结批次与回执支持重试去重。缺卡、拓扑重叠或旧策略上报时不会悄悄切换到其他接口。服务器配额按该服务器选定的计费方式计算（入站+出站、仅入站、仅出站或本期两方向取较大值）；节点、分享、固定转发各有自己的账本，不把它们重复相加作为服务器配额。

### 2.3 统一配额公式与对账

服务器和分享共用同一套四种计费公式，各自独立选择；分享跨服务器汇总方向后再计费。原始流量图、计入配额的用量和校准值分开展示。精确公式、订阅流量头投影、校准与采样边界见[统一流量计算](traffic-accounting.md)。

## 3. 节点监听与自定义出口

### 3.1 创建并绑定出口

1. 在“节点出口 → 出口方式 → 已有代理或本机网卡”中创建 direct、SOCKS5、SS-2022、SSH 或 WireGuard 规则。
2. 按需填写外层网卡、源地址、地址族和 DNS；认证字段按协议填写，SSH 必须校验主机公钥。
3. 在同页“选择节点并应用出口”中选择已有节点，再选择要引用的出口及固定版本。若需改变监听地址或客户端访问方式，仍在节点详情的网络设置中单独操作。
4. 查看影响预览，确认相关节点与共享进程重启范围后提交。
5. 等待匹配当前配置的应用回执，再用客户端验证实际连接。

出口内容按版本保存，修改模板或轮换凭据不会让已有节点自动追随新版本。编辑时可保留已有凭据；需要切换的节点须显式引用新版本。停用、删除和重新绑定会检查依赖；预览后依赖改变，需要重新预览。

监听地址须属于目标服务器的可用地址。客户端访问地址可继承服务器公网地址或单独指定；显式指定的地址不随服务器公网地址变动。恢复默认网络需要显式操作。

### 3.2 协议与运行条件

| 类型 | 适用范围与限制 |
|---|---|
| direct | 指定网卡、源地址、DNS 与地址族，保留宿主机路由语义 |
| SOCKS5 | 支持认证与可选 UDP；关闭 UDP 时业务 DNS 使用 TCP；特殊 UDP 中继兼容仍需核验 |
| SS-2022 | 使用适配的官方 sing-box；所需版本及升级步骤见运维文档 |
| SSH | 密码或内联私钥认证，必须固定主机公钥；仅 TCP，业务 DNS 使用隧道内 TCP |
| WireGuard | 配置 Peer、密钥、地址与 MTU；不是宿主机整机 VPN |
| Snell / mita | 支持指定监听地址，业务出站沿用宿主机路由，暂不支持绑定传输出口 |

内核、agent 能力、架构与本机条件都须通过预检。兼容版本和升级确认统一见 [内核版本与升级确认](operations.md#47-内核版本与升级确认)。配置兼容范围不等于所有协议组合和架构均已完成运行测试。

### 3.3 DNS、私网和故障处理

域名上游使用受限启动解析与到期刷新；相同 IP 续期不重启内核，地址变化先阻断旧路径再重新应用。控制端暂时离线时，agent 可按持久化的最新配置继续刷新和恢复，但恢复仍核对本机策略。

私网上游或固定转发目标必须在对应 VPS 本机进行窄授权，步骤见 [私网传输授权](network-transport-authorization.md)。节点的业务私网访问开关不能代替传输端点授权。

接口丢失、身份改变、地址失效、解析不安全或保护规则异常时，相关路径保持阻断，不回退直连；无关节点不应因此改变出口。先修复本机网络或授权，再检查最新配置回执，必要时从操作记录重试。不要通过手工放宽防火墙绕过预检。

### 3.4 多网卡与 SSH 出口示例

以已有两个接口、希望节点经第二个接口连接外部 SSH 服务为例：

1. 在“网卡与流量”确认第二个接口在线且身份已上报。计费接口单独选择，不能用计费设置代替路由设置。
2. 在“节点出口 → 出口方式 → 已有代理或本机网卡”添加 SSH 出口，填写 SSH 服务地址、认证方式及 OpenSSH 格式的主机公钥，选择第二个接口作为外层出口。不要跳过主机公钥校验。
3. 在一个 sing-box 节点的网络设置中引用该出口的固定版本；监听接口与订阅访问地址按客户端实际能到达的入口填写。
4. 预览影响范围并提交，等待与当前配置相匹配的应用回执。SSH 仅支持 TCP，业务 DNS 使用隧道内 TCP；不能据此宣称 UDP 已可用。
5. 从客户端请求域名和 HTTPS 站点，核对目标侧看到的出口。测试禁用出口后连接确实被阻断，再显式恢复并确认仍走选定接口；不得回退到默认直连。

改为 WireGuard 时创建 WireGuard 出口并填写 Peer、公钥、密钥、地址及 MTU；该出口供节点业务使用，不会自动成为宿主机整机 VPN。网卡删除重建会产生新身份，需重新预览并绑定；网卡改名与删除重建不是同一操作。当前 issue 修复和实际验收范围见 [GitHub issue 验证记录](github-issue-validation.md)。

## 4. 托管双端中转

1. 在入口服务器打开「节点线路 → 节点出口」，出口方式选择「另一台受管 VPS」，点击「添加中转」，选择入口节点和落地 VPS。
2. 选择 WireGuard 或 SS-2022；需要时展开高级设置，配置连接地址、网卡和 DNS。
3. 预览并确认两端影响。落地端先创建独立服务，入口在落地端确认应用前保持阻断。
4. 等待两端最新配置回执，随后验证客户端流量确实从落地端发出。
5. 不再使用时退役线路；系统先阻断入口，再撤销落地服务并结算最终流量。

任务持久化，可在进程重启后续办。活跃中转的两端不能直接删除服务器，托管出口也不能通过普通出口编辑器改写。域名或私网连接地址仍遵守解析与本机授权规则。

退役后入口保留停用出口引用，显式解除绑定才恢复默认路径。已退役线路可从常用列表移除，并通过“显示已移除记录”查看；历史流量与计量身份保留。

## 5. 固定端口映射

### 5.1 创建和修改

固定转发是独立资源，不是代理节点。配置监听端口、固定目标、允许来源、连接预算与出站规则，预览后提交并等待应用。直连支持 IP 或域名目标；经 SOCKS5、SSH、WireGuard 等已适配传输出口时，当前要求固定 IP 目标，具体组合以预检结果为准。

转发独立计量。修改端口时旧端口继续预留到清理确认；删除先退役，agent 持久化最终计量和清理收据，控制端结算去重并确认后才释放端口与本地状态。不能把“已保存”当成端口已释放。

### 5.2 明确限制

当前源码开放 TCP、UDP 与 TCP+UDP。UDP 需要新版控制端、具备会话回收能力的 agent，以及设置中保存的官方 sing-box 1.14.1 或兼容的稳定 1.14.x；旧发行附件不因此自动具备能力。直连、已开启 UDP 的 SOCKS5、WireGuard 出口可用，SSH 仅支持 TCP，私网 UDP 固定目标尚未开放。每条 UDP 会话上限 1–1024，整机启用转发的预算合计不超过 8192，空闲时长 2–600 秒。

agent 使用经过认证的本机临时 API 与只读 conntrack 观察回收空闲映射，实际关闭有轮询和保守确认延迟。会话管理连续故障时只关闭固定转发的 UDP 通路，TCP 与普通代理节点保留；恢复前清理残留 UDP 会话，再自动开放。独立健康租约最长六秒自动失效，不依赖控制端在线。超过 1024 的旧 UDP 记录保留，但会阻断启用，需减少上限后重新预览应用。面板展示最近会话数、累计清理次数及暂停原因，离线或过期诊断不会显示为正常。官方内核对零负载 UDP 报文可能关闭或重建映射，依赖空报文透传或保活的应用暂不支持。实现与验收见 [UDP 固定转发验证](udp-forwarding-validation.md)。

官方 sing-box 1.14.1 的 TCP 半关闭测试未通过。依赖发送 EOF 后继续接收响应的应用须单独验证。VpsCT 不通过修改或自行编译内核绕过这些限制。

## 6. 验证范围与后续能力

当前实际网络验证主要覆盖 Linux ARM64 隔离环境；AMD64 交叉编译通过不能代替实际流量验收。其他入口与出口组合、ULA 外层、复杂 NAT/MTU、物理网卡跨重启、原生 WireGuard 客户端以及携带网络资源的升级卸载仍有缺口。

Snell/mita 隧道出站、整机 VPN、任意多跳、自动故障切换和带宽叠加属于后续扩展。详细实验按日期保留在 [实施记录](network-implementation.md)，正式发布验收见 [发布流程](releasing.md)。

## 7. NAT 落地部署 Shadowsocks

1. 在商家面板配置端口映射，再在 VpsCT 的服务器页面填写并等待 agent 确认。
2. 点击“部署节点”，协议选 Shadowsocks。无需 TLS 域名或证书。
3. 加密方式可选 SS-2022 AES-128/256-GCM，或传统 SS 的 AES-128/256-GCM、ChaCha20-Poly1305；按客户端支持选择，凭据自动生成。
4. 传输默认“仅 TCP”，只要求对应公网端口的 TCP 映射。需要 UDP 转发时选择“TCP + UDP”，同一公网端口必须同时具备两种映射。
5. 留空公网端口会从匹配所选传输的商家映射池分配。订阅同步写入 UDP 开关；通用 `ss://` 链接不携带此开关，仅 TCP 节点手动导入后需在客户端关闭 UDP。

更新控制端和 agent 后使用新增选项。已有 SS 节点和分享自动生成的 SS 节点继续使用原来的 SS-2022 与 TCP+UDP；重置凭据保留节点的加密方式和传输选择。

## 8. 配置两台或三台转发线路

落地节点仍负责代理认证和出网，但不必占用独立的第 3 台机器：两台模式为「入口 → 落地节点」，第 2 台直接运行节点；三台模式为「入口 → 中转 → 落地节点」。

使用前，确认所选机器之间的线路和路由已接通。入口和中转必须加入面板；受管落地也需加入面板，导入或手动节点可使用外部服务。面板配置软件转发，不提供或购买专线。

1. 选择落地节点：可使用受管服务器部署的节点，也可使用导入或手动添加的外部节点。入口和中转不需要部署代理节点。
2. 打开任意相关服务器的「节点线路 → 转发线路 → 创建线路」，先选择线路结构（默认三台），再选择入口、中转服务器和落地节点。无需额外中转时切换为两台，只选择入口和落地节点。节点选项同时显示服务器与节点名称，不必另选落地服务器；协议、端口和认证自动读取，线路自动命名，监听端口自动分配。
3. 需要自定义连接时，展开对应机器下的可选设置：入口设置包含接入地址、监听端口和来源限制；入口到中转设置包含中转连接地址、监听端口和入口出站路径；落地设置包含连接地址和该段出站路径。两台模式在「入口 → 落地设置」中配置地址和入口出站路径，不需要中转地址或监听端口。走专线内网时填写对应段的内网地址。各段端口可不同，NAT 服务器自动分配使用已确认的商家映射，路由仍须事先配置。
4. 点击「检查配置」，核对实际转发段的条件和共享进程重启影响，再提交。系统持久化线路、一段或两段转发及独立订阅，等待落地节点应用；两台模式随后开放入口，三台模式先配置中转、再开放入口。关闭页面或控制端重启后仍继续执行。
5. 各转发段匹配当前配置的应用回执确认后，可复制接入节点或查看自动生成的订阅。订阅使用入口地址与端口，以及落地节点当前已应用的认证参数；不会改写原落地节点，仍需客户端实测线路。
6. 在订阅编辑器的「节点与线路」中，可将这条线路加入其他生成订阅。线路须独立勾选，不随「包含全部节点」自动加入；名称过滤同样适用。落地节点撤销、分享失效或对应入站配额耗尽时，不再输出该线路。线路和原节点同时被选中时，源节点流量只计一次；多个入口共用同一源节点时，无法据此拆出每条线路各自贡献的落地流量。
7. 不再使用时选择「停止并清理」。先撤下订阅接入并清理入口，收到最终计量和清理确认后再清理可选中转段；离线端等待恢复，端口确认清理后才释放。落地节点及其他线路保留。线路拥有的转发不能通过普通转发编辑器改写。

转发线路支持 SS、VLESS、VMess、Trojan、AnyTLS、Snell、Mieru、Hysteria2、TUIC、WireGuard，以及 TCP SOCKS5/HTTP 节点；只接受本产品可表示的传输参数，未知传输会拒绝。Hysteria2、TUIC、WireGuard 和 UDP Mieru 需要 TCP+UDP 转发；VLESS 等协议可在 TCP 内承载业务 UDP，不会因选择 TCP 转发被误禁用。SOCKS5 UDP-associate 的动态端口不属于固定转发范围，因此接入配置关闭其 UDP。受管节点需匹配当前应用回执；外部节点只有面板管理的转发段回执，不代表上游已经通过连通性验证。已有隧道出口的受管落地节点不能作为该线路的落地。公网 UDP 沿用固定转发的官方内核和新版 agent 要求。私网 TCP 创建后会保持入口关闭，并显示实际转发段 ID；由相应 VPS 的 root 按[本机传输授权](network-transport-authorization.md)配置该 ID、固定地址和端口的 `forward_grants`，等待 agent 上报后自动继续。私网 UDP 固定目标仍未开放。域名目标需要选择具备 DNS 的直连出口，TCP 半关闭及零负载 UDP 限制仍按第 5 节执行。

“配置已应用”代表控制端核对了应用回执，不表示已完成真实端到端连通性测试。agent 管理连接暂时离线不等同于代理断线；已确认的数据路径不单因管理心跳过期而改走其他出口。源节点或已知配置条件失效时，订阅立即停止输出，后端协调阻断入口；远端阻断需要对应机器能接收配置，不能承诺瞬时跨机关闭。

### 8.1 外部落地的端点和订阅变化

默认使用外部节点原地址和端口，生成的接入配置保留协议、认证、Reality、TLS 和传输参数；原配置依赖服务器名称的 SNI、WebSocket Host 等会显式保留，避免替换接入地址后改变身份。域名目标需在「入口 → 落地设置」或「中转 → 落地设置」选择带 DNS 的直连出口，也可填写实际连接 IP。

外部节点更新认证参数后，接入订阅使用当前参数；地址、端口或协议变化会立即撤下输出并协调关闭入口，需重新配置线路。上游删除正在使用的节点时，保留停用且撤销的节点记录，以便关闭入口；同一订阅其他节点仍能正常同步。删除正在被线路使用的外部订阅前，须先停止线路并完成清理。

### 8.2 VLESS 等节点绑定出口中转

「节点出口 → 出口方式 → 另一台受管 VPS」的前置节点支持已部署的 VLESS Reality、Trojan、AnyTLS、Hysteria2、TUIC 和 SS；后段可选择托管 WireGuard 或 SS-2022，前置协议和客户端凭据保持不变。Snell/Mieru 独立内核及 WireGuard 接入不在此出口编排范围。导入节点属于外部服务，面板不能修改它的服务端出口；可将其作为两台或三台转发线路的落地。

非原有 SS-2022 AES-128 入口需要上报 `network_proxy_inbound_version=1` 的新 agent。旧 agent 会提示升级；保存配置不会自动升级锁定内核。VLESS Reality 的伪装握手通过已选外层 DNS 受限解析，拒绝私网、本机和元数据地址，固定解析到的公网 IP 后再经后段传输连接；业务 DNS 与流量继续走后段。握手域名按缓存时限重新解析，解析失败保持阻断，不回退直连。

`GOCACHE=<可写缓存目录> python3 scripts/test-proxy-inbound-container.py` 可复现官方 sing-box 1.14.1 的隔离 VLESS Reality → SS-2022 → HTTP 实际会话，目标确认来源为落地容器。该测试使用文档地址并仅在隔离配置中明确允许该测试目标；不替代真实 VPS 的路由、私网授权、UDP 会话及其他架构验证。新的组合另有控制端、agent、编译器、上游节点刷新和订阅身份保留的回归测试。

8192 是配置预算的安全上限，并非承载能力保证。默认 256 MiB 代理预算的发布验收基线为 1024 个持续活跃 UDP 会话；原生 AMD64 的 8192 会话强负载尚未通过，会触发 API 不可用保护。请按资源和实际负载控制并发，不能将其换算为固定用户数。
