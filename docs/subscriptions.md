# 节点、订阅与分享

[返回 README](../README.md) · [网络与中转](network.md) · [隐私说明](privacy.md)

## 1. 节点库与客户端格式

节点库包含已部署节点、导入节点和链式节点。订阅从节点库生成，或转换外部订阅；不提供配置文件上传与托管。旧上传记录保留数据，但不再提供下载。

订阅导入节点可在「节点」列表点击右侧铅笔按钮重命名，也可在详情中编辑名称。自定义名称用于订阅输出；同步仍按上游原名匹配，保留节点 ID 和自定义名称，并更新连接参数。上游删除该节点时，本地节点也会随同步移除；上游改名仍按删除旧节点、新增节点处理。

### 1.1 协议与导出

SSH、WireGuard、Mieru 提供结构化客户端参数编辑。SSH 使用密码或内联私钥，并固定主机公钥；不接受任意本地密钥文件路径或跳过主机校验。WireGuard 支持受限标准配置导入，不执行 PostUp 等脚本。

| 协议 | 当前输出与注意事项 |
|---|---|
| VLESS / Trojan 普通 TLS | TCP、WebSocket、gRPC 的 Mihomo、sing-box、明文 URI 和 Base64 输出分别保留传输及证书校验。WebSocket 保留路径和独立 HTTP Host，gRPC 保留服务名。 |
| SSH | Mihomo、sing-box outbound；仅 TCP，不生成通用分享 URI |
| WireGuard | Mihomo、sing-box endpoint、可等价表达时的标准 WireGuard 配置；原生客户端运行验收另行记录 |
| Mieru | Mihomo 配置；服务端由 mita 部署，sing-box 不输出不支持的 Mieru 节点 |
| Snell | 按客户端格式输出；Mihomo 排除不支持的高版本及其依赖链，不修改原节点版本 |
| Shadowrocket 的 Snell | 使用原生 password、version 等字段，保留 UDP、复用与链式参数 |
| Shadowrocket 的 VLESS REALITY | 使用原生 pbk、sid、fp 字段 |

协议被过滤时，相应组引用也需要有效；不能靠伪造版本或生成不等价字段让客户端导入。界面只展示该节点可用的配置片段，不为没有通用 URI 的协议生成空二维码。客户端支持范围以相应渲染器和实际验证为准。

普通 Surge 链接使用兼容档。需要 VLESS 时，可显式选择「Surge（iOS 6.1+ / Mac 6.13+）」并按完整托管配置载入。链接、预览和托管更新使用同一 `profile=surge-vless`；客户端版本未知时不会自动进入此档。版本验证范围见 [v0.1.9 发布说明](releases/v0.1.9.md)。

现代 Surge 档可表达 VLESS WS/gRPC；普通档保留 Trojan WS。Trojan gRPC 在两个 Surge 档都过滤。Shadowrocket 原生配置暂不输出 gRPC；可按客户端实际能力选择 URI 或 Base64。各格式会剔除不能完整导出的入口；可用入口数见订阅预览。

### 1.2 外部订阅信息项

上游可能把剩余流量、到期时间等提示伪装成节点。导入与渲染会排除完整匹配的信息标签，旧记录无需删除即可停止进入代理列表；仅名称含类似词语的真实节点仍保留。只有信息项的同步响应不会清空原有真实节点。

## 2. 模板、预设和订阅链接

模板是客户端收到的完整底稿，包含 DNS、代理组与分流规则，一种模板对应一种格式。预设仅覆盖订阅的代理组与规则，两部分应一起选择；不选预设时沿用模板。预设本身不可下载，分享也不使用这两项预设字段。

被分配分享的成员可在分享详情创建个人模板，或复制内置模板后编辑；再分别为 Mihomo、Surge、Shadowrocket 和 sing-box 预览并应用。模板仅本人可管理，正在使用的模板应复制后修改并重新应用；删除模板会使引用它的分享恢复原有默认。Base64 和 URI 链接不套完整配置模板。客户端需要更新订阅才会获得修改，分享转交其他账户时清除原用户的个人模板选择，既有订阅链接不会因此自动轮换。

管理员可分别委派公共模板的创建、编辑和删除。对于他人的分享，受委派成员需要 `shares.view` 查看授权范围内的状态和配额，还需 `shares.links` 才能读取订阅链接与节点凭据。成员为自己分享选择个人模板时按分享归属校验。具体委派操作见 [AI 接口权限说明](agent-api.md#16-功能覆盖与执行边界)。

分享详情页使用随机生成的稳定标识；原来的数字详情页地址已停用。页面标识不是订阅凭据，查看详情仍须登录并拥有相应权限；已有的客户端订阅链接不会因地址调整而改变。

模板通过正文编辑；Mihomo 模板使用 YAML。管理员可在节点列表填写经核实的出口地区；地区标记如 `{{region:JP}}` 优先使用节点出口地区，其次使用服务器地区或按节点名称保守识别。无法确认且未手动设置的自定义出口进入 `{{region:UNKNOWN}}`，不会启用在线 GeoIP。链式和转发线路以落地节点的地区为准。筛选无匹配节点时移除空地区组，其他组不再引用它；规则直接引用该空组时预览报错，需选择可用策略。已有使用名称正则的自定义模板不会自动改写。

内置 Mihomo 模板会为其他已知地区自动生成代码命名的地区组，并加入手动选择组；未知节点留在未分类组。自定义模板可以设置 `x-vpsct-other-regions: true` 并在组成员中使用 `{{other-regions}}`，生成时会移除该内部字段和标记。

Mihomo 个人模板可用当前分享节点预览未保存的 YAML 草稿；预览可能包含节点连接凭据，需妥善保管。保存及应用是两个操作，应用成功后客户端更新订阅才会生效。

模板每次修改前会保留旧版本，最多保存 30 个加密历史版本；可从历史版本创建副本，检查后选择应用。已在使用的个人模板仍须通过副本更改，避免直接破坏当前配置。历史记录自此功能启用后开始积累，删除模板时一并删除。

浏览器直接打开订阅链接时显示使用提示，返回 403，响应不缓存，不直接下载配置；显式格式和短链接同样处理。应把链接添加到对应代理客户端。此识别用于区分浏览器导航，不能代替订阅 token 的访问控制；链接仍应作为凭据保管。

## 3. 部署、分享与网络继承

mita 支持自动部署、TCP/UDP 传输、节点计量、凭据轮换与删除。WireGuard 接入采用单用户 Peer；不能将一个私钥当作所有分享的公共模板。

分享目标可以保存监听与出口网络模板。新建专属入口时复制网络设置和固定出口版本；已有入口、重签与恢复不会因模板后来变化自动改线。Snell/mita 继承监听配置仍受独立内核出口限制约束。

分享按各自凭据、用量与有效期管理，原始计量保留入站和出站，不额外乘二。配额与服务器共用四种计算公式，分享独立选择方式，默认双向；跨节点汇总本期方向后再计算计费，订阅流量头与该配额结果一致。额外复用的现有节点不具有分享独立计量身份，不能将它们的全部用量归到这份分享。公式与采集边界见[统一流量计算](traffic-accounting.md)。暂停后的订阅排除相应专属节点，已下载凭据的停止使用还需节点配置实际收敛。保存、配置下发、应用回执和客户端连通是不同阶段。

### 3.1 分享内的节点额度

创建或编辑分享时，可为每个勾选的「服务器 × 协议」入口填写独立额度（GiB），留空或 0 表示该入口不限量。节点额度与分享总额度同时生效：单个节点用尽只停止该入口并从订阅中排除，分享总额度用尽则停止整份分享。停止转发须等待 agent 应用配置，采集与下发之间可能有少量超用。

每个节点沿用分享的计费方式、账期与重置日，先累计该节点本期的原始入站和出站，再计算配额；切换计费方式或修改额度不会清零。自动换期和手动重置分享用量会同时清零节点额度用量，重新签发凭据保留用量。详情页显示各节点的已计量用量、额度及用尽状态。附加节点复用已有凭据，无法独立计量或限制这份分享的用量，因此不提供节点额度。

已有分享升级后，节点额度用量从支持此功能的版本首次运行后开始累计，不回填可能已被清理或跨越手动重置边界的历史图表；原有分享总用量与总额度不变。

## 4. 排查与验证

1. 确认客户端格式支持节点协议和版本，更新订阅后检查实际节点列表。
2. 检查模板最终选择的代理组，不能仅以单节点测速成功证明分流正确。
3. 检查订阅中的访问地址；自定义访问地址和继承服务器公网地址的行为不同。
4. 网络绑定或中转异常时，按 [网络指南](network.md) 查看预检、出口版本和应用回执。
5. 分享不可用时同时检查配额、有效期、暂停状态和专属节点应用状态。

公开模板与分享订阅的 ARM64 官方客户端贯通测试见 [验收记录](readiness.md#8-官方内核与公开订阅贯通验证)。该记录不代表所有客户端、任意自定义模板或全部架构均已验收。
