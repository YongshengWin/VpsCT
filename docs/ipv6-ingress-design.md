# VpsCT 仅 IPv6 节点与独立 DDNS 设计

本文定义从服务器配置、首次部署到 IPv6 地址轮换的产品行为与实现契约。字段和接口名称为设计提案。

当前迭代实现了独立 `public_host_ipv6`、地址草稿检查、首次仅 IPv6 监听、外部 DDNS 复核、现有节点迁移、按节点 ID 查应用结果，以及本机预备包安装。实际接口见 [API 使用说明](agent-api.md)，主机准备见 [离线附件](operations.md#410-纯-ipv6-被控机的离线附件)。自动监听要求所选接口有唯一的稳定公网 IPv6。IPv6 字面量可手动发布，自动发布 agent 地址、多地址自动选择和独立公网探测仍待实现。地址改名时先解除依赖节点的继承，本期使用现有节点 ID 查询结果。

隔离测试已验证无 IPv4 地址和默认路由时的离线 agent 安装及 IPv6 HTTPS 注册、官方内核离线安装与校验，以及真实 nftables 对 IPv6、IPv4 和 IPv4-mapped 流量的判定。本地 AMD64 容器的 seccomp 预检失败，完整 AnyTLS 连接仍需在具备所需隔离能力的 Linux AMD64 环境验证。

## 1. 产品目标

用户可以在同一台双栈服务器上同时运行普通节点和仅 IPv6 接入的节点。创建仅 IPv6 节点时，直接选定客户端访问地址和监听策略。第一次启动时只有 IPv6 能访问该节点。部署完成后，订阅和分享使用这台服务器独立的 IPv6 DDNS 名称。

「仅 IPv6 接入」约束客户端到 VPS 的连接。VPS 到目标网站的出站沿用现有出口策略。需要 IPv6 出站时，用户可以单独绑定「业务地址族 → 仅 IPv6」的直连出口。本功能解决入口配置、地址管理和 IPv6 强制监听，YouTube 等目标的吞吐量按实际出站路径评估。

首版覆盖独立公网 Linux AMD64 服务器及通过验收的官方 sing-box 协议。服务器现有「公网地址」继续用于原来的入口与默认行为。服务器和节点均可在新旧配置间并存。

独立公网包括只有公网 IPv6 的 VPS。新机接入、内核安装和后续升级的兼容范围见第 6.2 节。

## 2. 面板交互

### 2.1 编辑服务器

在现有「公网地址」旁新增「IPv6 公网地址」，接受公网 IPv6 或独立域名。空值表示尚未配置服务器级 IPv6 默认地址。保存新增或修改的地址时，按钮显示检查进度，检查失败时在 IPv6 字段旁提示原因并保留表单。

保存域名时检查仅有一条公网 AAAA，近期可信网卡清单可用时核对地址归属。服务器可以先保存并等待 agent 注册。仅 IPv6 节点部署时重新核对地址族和归属。删除或替换字段前，须先为仍继承此字段的节点配置独立地址或迁回普通接入。

DDNS 的 AAAA 由用户已有的 DNS 服务或客户端更新。面板记录域名并观测更新。固定地址可以直接填公网 IPv6。用域名时，界面提示只设置 AAAA，有代理开关时使用仅 DNS，由客户端直接连接节点。 [DDNS 更新方式](https://developers.cloudflare.com/dns/manage-dns-records/how-to/managing-dynamic-ip-addresses/)

### 2.2 部署节点

在「部署节点」弹窗增加「接入方式」，默认沿用服务器原设置，另一项为「仅 IPv6 接入」。选择后在同一弹窗展示以下字段。

| 字段 | 默认值与操作 |
|---|---|
| 客户端访问地址 | 继承「IPv6 公网地址」，并显示将写入订阅的主机名或 IP。也可为本节点指定独立的 IPv6 地址或 AAAA-only 域名。服务器 IPv6 字段为空时，需明确选择从 agent 的已验证本机 IPv6 发布，或填写独立地址。 |
| 节点监听 | 默认「跟随本机公网 IPv6」。固定地址或多网口主机可选择「指定本机 IPv6」。存在多个符合条件的接口且无法唯一判断时，表单要求选接口。 |
| 端口和协议 | 保留原部署字段及端口分配规则。明确提示该协议需要开放的 IPv6 TCP 或 UDP 端口。 |
| TLS 域名 / Reality 伪装域名 | 保持协议语义。新建常规 TLS 节点时，访问地址为域名可预填 TLS 域名。Reality 握手域名单独配置。 |
| 节点出口 | 提示当前出口及地址族，默认沿用宿主机。既有出口编辑器负责出站变更。 |

用户提交前可看到接入地址、端口、本机监听、TLS 名称和预检结果。自动分配时允许初次预览不占端口。提交事务以预览确认后的端口为准，冲突时返回可重试的冲突并重新预览。能力、DNS、接口或端口冲突用具体错误说明。部署后在节点详情原位展示应用状态，回执满足发布条件后开放复制链接与二维码。

### 2.3 节点详情

单列显示「接入方式」「客户端访问地址」「实际监听」「业务出口」「DNS 状态」和「应用状态」。DNS 待同步、agent 未确认、监听失效和公网不可达分别显示。控制端没有外部探测能力时，公网可达性显示「未验证」。用户可对已有普通节点发起单节点迁移，保持节点 ID、端口、凭据、流量和分享关系。迁移预览展示地址变更、订阅刷新和共享进程重启影响。恢复普通接入走同样的显式预览和应用流程。

## 3. 数据与地址解析

### 3.1 持久化模型

| 位置 | 建议字段 | 含义 |
|---|---|---|
| 服务器 | `public_host_ipv6` | 可选的公网 IPv6 字面量或规范化域名。原有 `public_host` 保持现有语义。 |
| 节点 | `ingress_family` | `default` 或 `ipv6`。随节点持久化，独立于可清空的网络自定义项。 |
| 节点网络 | `listen_mode` | 现有 `all`、`address`，新增 `public_ipv6`。IPv6 节点只允许后两种，且 `address` 必须为符合条件的本机 IPv6。 |
| 节点网络 | `advertise_mode` | 沿用 `inherit` 与 `override` 的编辑语义，新增 `inherit_ipv6` 和 `agent_ipv6`。仅 IPv6 节点可用 `inherit_ipv6`、显式 IPv6 `override` 或 `agent_ipv6`。 |
| 节点运行状态 | `effective_host`、`listen_address`、`dns_status` 及回执 | 从当前配置和可信观测派生。保留最后已应用端点用于排查。节点的配置版本与每次运行地址变化的观测序号分别记录。 |

数据库迁移给已有节点写默认值，保留既有字段与当前继承行为。服务端更新用可区分省略和清空的字段，旧调用者提交修改时省略新字段即保留原值。普通节点的 IPv4 兼容行为继续由已有逻辑处理。迁移版本支持前先备份数据库和密钥，旧控制端恢复使用匹配的备份。

### 3.2 客户端地址解析

| 接入与来源 | 订阅地址及失效行为 |
|---|---|
| 普通接入 | 按现有服务器地址或节点覆盖规则解析。 |
| 仅 IPv6 + 继承服务器 | 使用 `public_host_ipv6`。缺失、失配或尚未确认时显示具体状态，按发布条件处理。 |
| 仅 IPv6 + 节点独立地址 | 直接使用该公网 IPv6 或 AAAA-only 域名。 |
| 仅 IPv6 + agent 地址 | 使用 agent 对该节点已确认的实际监听 IPv6。地址变化后新生成的配置包含新 IP，已导入配置需刷新。 |

同一个业务解析函数供节点详情、列表、URI、二维码、订阅、分享、客户端专用配置、链接再生成和线路引用使用。将 API 和订阅各自建设服务器地址表的逻辑收敛到该函数。服务器编辑和 agent 心跳的更新条件按地址来源区分，普通公网地址或 IPv4 上报不能覆盖 IPv6 专用节点。用于确认 IPv6 监听的地址只能来自 Agent 网卡观测和回执，管理 HTTP 连接的源地址不能替代。

仅 IPv6 地址输入规范化后禁止端口、URL、作用域、IPv4-mapped 地址和非公网地址。对域名分别检查 A 和 AAAA，限制 CNAME 深度、答复大小、查询并发和超时。首版仅支持一个可用 AAAA，且它必须匹配获准监听接口上的本机公网 IPv6。多个 AAAA、A 记录、代理 CDN 地址与暂未同步分别返回可处理的状态。查询通过既有受约束的网络设施完成，只对合法的公开域名做 DNS 查询。面板、日志和审计记录状态码与配置版本，避免复制无关连接或凭据信息。

转发线路引用仅 IPv6 节点时，也要验证该段的目标、解析结果和传输出口是否允许 IPv6。相关线路使用已保存的显式目标时，预览列出仍依赖旧目标的线路。用户选择并确认后逐条迁移，避免静默改写线路。

## 4. Agent 与运行时

### 4.1 第一次应用即仅 IPv6

控制端把接入地址族、监听模式和来源意图写入首次 desired。Agent 以新鲜的本机观测选择具体的公网 IPv6，将官方内核绑定到该地址。继续用现有 nftables 网络守卫对节点端口约束地址族、目的地址和接口。IPv4 限制在服务启动前生效，覆盖节点声明的 TCP/UDP 以及本机回环可达的路径。内核应用必须核对实际监听和候选版本，失败则关闭这个节点的入口。

不能把现有的 `[::]:port` 通配监听直接视为仅 IPv6。IPv6 socket 可以接受 IPv4-mapped 流量，实际行为取决于应用的 socket 设置。使用具体 IPv6 加节点级守卫可沿用官方内核与项目现有隔离，不依赖宿主机全局 sysctl。 [IPv6 socket 规范](https://www.rfc-editor.org/rfc/rfc3493.html#section-5.3) · [sing-box 监听选项](https://sing-box.sagernet.org/configuration/shared/listen/)

IPv6 接入和现有服务器「出站仅 IPv4」可独立组合。当前绑定校验将后者也用于拒绝 IPv6 监听，实施时须把新的仅 IPv6 入口校验与出站策略分离，并保留历史节点和转发资源原有判定。测试其中的 AnyTLS、Reality 握手和 ACME 管理流量，避免接入选项意外改变业务、握手或管理出站。

### 4.2 IPv6 变化、接口更换与恢复

- 「跟随本机公网 IPv6」使用 agent 网卡清单，排除 IPv4-mapped、ULA、链路本地、临时、弃用、DAD 未完成和重复归属地址。对 DDNS 模式，AAAA 只能在允许的本机候选中确认一个地址。对显式选择 agent 地址的模式，优先保持仍合法的当前地址，没有当前地址时只采用唯一候选。预览里的缓存只供提示，agent 应用时重新检查。
- IPv6 地址变化触发本机重算。新地址先进入本机候选，DDNS 更新后核对 AAAA，再按原端口应用。旧地址与旧绑定仍可用时可以在 DNS 短时异常或更新等待期间继续服务并标记降级。确定 AAAA 指向不匹配的地址时，暂停新导出。旧地址失效或接口身份不再可信时，阻断节点，等待候选就绪。切换可能中断已有连接，DNS 缓存仍受 TTL 影响。
- 本机事件和有界的 DNS 刷新共同触发重新核对。连续相同结果合并，不反复重启内核。应用前后保持同一节点、端口、凭据、计数器与计费策略。接口改名沿用同一可信身份，删除重建或无法证明身份时暂停并要求重新确认绑定。agent 重启仅可根据最新已接受的意图和新观测恢复，不能从旧缓存恢复已经撤销的配置。控制端短时离线时沿用已接受意图的本地核验，回执在重连后补报。
- 「指定本机 IPv6」严格固定所选地址。消失时阻断，原地址恢复才自动恢复。若要随地址变化，使用「跟随本机公网 IPv6」。

### 4.3 TLS 与可达性

新建 AnyTLS、Trojan、Hysteria2、TUIC 时，把确认后的 TLS 名称和证书模式写入原有协议配置。固定访问地址可以与 TLS 名称不同，客户端使用证书对应的显式 SNI。IPv6 字面量搭配 ACME 时，首版要求另填可验证的证书域名并通过现有证书预检。DDNS 的 AAAA 轮换维持同一 TLS 名称。修改 DDNS 主机名时，在预览中区分连接地址和证书名称，用户按现有证书流程选择是否更换 TLS 名称。Reality 的握手与公钥配置保持原协议语义。

分别检查 agent 已应用、DNS 一致与公网可达。部署时提示云安全组和宿主机防火墙要求。可选公网 IPv6 探测只访问已验证归属的节点，并按 TCP、UDP 协议使用不同的验证场景。证书、握手或外部端口未就绪时准确显示所在阶段。

## 5. API、一致性与发布条件

### 5.1 创建与确认

建议复用已有服务器表单和接口，增加只读的 `GET /api/v1/servers/{id}/ipv6-endpoint` 返回地址来源、DNS 核验结果、最后核验时间和候选是否匹配。自动检查走同一有界观测任务。节点部署回执可通过现有节点详情和网络操作接口查询。

| 结果 | 面板行为 |
|---|---|
| `waiting_agent` | 显示已提交和待应用版本。 |
| `waiting_dns` | 显示待解析、AAAA 未同步或观测已过期，提供重新检查。 |
| `applied` | 回执确认 IPv6 监听。DNS 已通过时开放下载。公网探测结果单列。 |
| `degraded` | 显示原绑定仍在运行及过渡原因。最后已验证的监听仍可用，且 DNS 尚无确定失配时，可以在短时宽限期内继续导出。 |
| `blocked` / `failed` | 显示阻断或失败原因、适用版本和处理动作。 |

1. 保留 `POST /api/v1/servers/{id}/nodes`，为仅 IPv6 部署增加 `ingress_family`、初始 `network`、访问地址覆盖和操作 ID。增设同资源的部署预览 `POST /api/v1/servers/{id}/nodes/preview`，复用现有地址、入口策略、出口引用、能力和影响校验。
2. 提交重新校验服务器配置、网卡观测、节点端口与相关版本。将节点、初始网络、分配的端口、幂等键、审计和待发布任务作为一个持久化提交。请求重试返回同一节点和任务。同一操作 ID 配不同请求返回冲突。端口分配按现行跨地址族互斥。
3. 发布任务可重试，控制端重启后能恢复。Agent 仅接受带新入口能力版本的完整 desired。旧 agent 或不匹配的官方内核在预检中明确提示。带仅 IPv6 节点的服务器禁止退回无法兑现该策略的 agent。无效候选保留普通节点的已知安全配置，IPv6 节点继续遵守其已确认边界。
4. 用稳定节点 ID 和任务 ID 查询状态。复用节点应用和网络操作回执，扩展事件携带节点配置版本、desired 版本与 hash、运行观测序号和已确认的地址族。报错区分 DNS 未同步、接口失效、版本不兼容、端口冲突、内核失败和超时。HTTP 成功只意味着创建或接受。超时先查同一任务，安全地重试发布或提交相同请求。
5. 节点详情、订阅和分享使用相同的可发布判定。首次只有在当前版本回执确认仅 IPv6 监听、且发布地址通过校验时才导出。仅保留原有有效绑定的短时 DNS 故障显示降级。确认失效或应用失败后，新生成的订阅和分享跳过这个节点并保留其他节点。已经下载的配置仍由客户端缓存，入口守卫继续执行。

旧节点的「恢复默认网络」对仅 IPv6 节点恢复该地址族下的默认监听和继承选择。没有合法地址就进入等待或阻断。退出仅 IPv6 模式必须走显式迁移，旧修改请求与节点重置都不能隐式放宽入口。

### 5.2 网页和自动化

沿用统一路由注册和权限链，让网页与 Bearer API 使用同一部署、预检、应用和审计服务。能力文档公开实际字段、枚举、条件限制、错误码以及从预览到应用的查询路径。覆盖 API key 读写 scope、角色、服务器和节点归属、Bearer 无 Cookie 创建、失败恢复与重试。同步 capabilities workflows、`docs/agent-api.md`、`skills/vpsct/` 和安装操作文档，并运行 `go generate ./internal/api`。

## 6. 支持范围与实施顺序

### 6.1 首版与后续

第一步交付服务器独立 IPv6 公网地址、原子创建、明确的监听和发布回执。先验收基于 sing-box 的 AnyTLS、VLESS Reality、Shadowsocks、Trojan、Hysteria2 和 TUIC，再按运行矩阵开放对应选项。第一步也包含已部署节点的同 ID 迁移，以及使用外部 DDNS 的地址轮换。独立 Snell、mita、用户态 WireGuard 接入、商家 IPv4 NAT 映射和分享自动部署应逐入口通过同等级验收后再开放创建。普通订阅及手工分享可立即引用已应用的仅 IPv6 节点。

后续可增加产品内 DDNS 写入。先确定用户实际使用的提供商，再从一条明确授权管理的 AAAA 记录做起。以记录标识和域名双重校验、最小权限凭据、加密存储或主机侧专用凭据、幂等更新、限频、结果读回和失败诊断组成独立作业。保留现有 IPv4 记录和同域其他记录的所有权。用户可选择继续由外部 DDNS 管理。

### 6.2 纯 IPv6 VPS 的安装和升级

纯 IPv6 VPS 指被控机拥有可路由的公网 IPv6，且没有可用的 IPv4 外网。界面允许将原「公网地址」留空，只填写「IPv6 公网地址」。agent 通过可经 IPv6 访问、TLS 证书有效的控制端地址注册并同步。控制端可以位于双栈主机，或通过支持 IPv6 的 HTTPS 入口提供服务。被控机不开放额外管理端口。

现有 agent 安装器会下载官方 GitHub Release 附件并安装发行版依赖，首次部署 sing-box 也可能访问上游下载地址。纯 IPv6 网络能否直接完成这些步骤取决于每一处来源的可达性。仅验证控制端可达，仍缺少一条能覆盖新机的安装路径。 [当前 agent 安装器](../internal/assets/install-agent.sh#L73) · [当前内核下载实现](../internal/core/install.go#L285)

建议把**固定版本的离线安装与升级**纳入纯 IPv6 新机验收。已有在线安装方式继续适用于能够访问所有来源的环境。

1. 在可访问官方源的可信机器上，按发行版本和 Linux AMD64 目标平台准备 agent 安装器、agent、验证与恢复工具、卸载器和官方校验材料。另准备与控制端所选版本、目标 libc 匹配的官方 sing-box 归档及其可信校验材料。系统依赖可由目标机通过可达的发行版软件源安装，或从官方发行版仓库提前备齐并通过系统包管理器校验。
2. 经用户授权的主机工具把文件传到目标机。安装器增加仅由本机操作者指定的离线附件入口，检查来源凭据链、版本、平台与校验值。离线模式直接消费已准备资产，缺件或校验失败时在替换程序前退出。已注册主机沿用原有权限检查和数据目录。
3. agent 使用一次性令牌，通过 IPv6 HTTPS 注册。内核由本机维护入口从已验证归档导入，继续复用原有解包预算、校验、原子替换和回退逻辑。面板等待 agent 上线和内核就绪后才允许首次部署。离线配置中控制端不得下发任意附件路径、下载地址或命令。
4. 对无法直达上游的主机，后续 agent 和内核升级复用相同的预备包与明确版本。自动更新在缺少目标版本材料时报告「等待安装包」，保留上一套可用程序与配置。材料到位后继续既有维护任务。可选的 IPv6 可达制品服务仅分发实际已发布、可独立核验的固定版本附件。

纯 IPv6 主机通过默认直连访问具备 IPv6 的目标。对仅有 IPv4 的网站，另选能到达 IPv4 的独立业务出口，例如经 IPv6 接入的双栈中转。部署与升级的下载路径和业务出口各自验证。首版使用无需外部握手服务器的协议完成最小验证，再按协议验证 Reality 握手目标、ACME 与证书续期的 IPv6 可达性。

### 6.3 验收

| 场景 | 通过条件 |
|---|---|
| 双栈 VPS 新建仅 IPv6 节点 | 创建表单一次提交。首次启动即拒绝 IPv4 和 IPv4-mapped 流量，IPv6 正向 TCP/UDP 按协议通过，普通节点仍可访问。 |
| 没有公网 IPv4 的已接入 VPS | agent 可通过 IPv6 连接控制端，完成首次应用、回执和公网 IPv6 客户端连接。 |
| 纯 IPv6 新机从零接入 | 阻断 IPv4 外网和上游直连，在隔离环境用预备包完成依赖安装、校验、注册、内核就绪、部署、订阅与客户端连通。分别验证错误版本或校验失败、升级后可用、故障回退和计量继续。 |
| DDNS 创建与轮换 | 验证正确 AAAA、AAAA 拼错、额外 A、多个 AAAA、CNAME、TTL、DNS 超时、地址先变或 DNS 先变、双地址过渡、旧地址丢失、重启与离线恢复。 |
| 安全边界 | 无有效 IPv6 时不能用通配地址回退。检查 IPv4 TCP/UDP、回环、IPv4-mapped、本机地址时序、陈旧回执、旧 agent、端口复用和共享进程错误回滚。 |
| 客户端输出 | Surge AnyTLS、Mihomo、sing-box、原始 URI 与二维码使用正确地址及 SNI。IPv6 字面量在 URL 中有方括号。分享、订阅刷新、外部链路引用使用同一解析结果。 |
| 幂等与兼容 | 旧设施保持原连接方式，旧 API 更新保留新字段，重复部署只生成一次，节点迁移与地址轮换不更换凭据或丢失计数。 |
| 故障诊断 | 面板和 API 能区分配置接受、DNS 一致、IPv6 监听已应用、外部端口可达。自动化能按任务 ID 判定最终结果。 |

组合使用隔离 IPv4/IPv6 网络命名空间和原生 Linux AMD64，运行官方内核、真实 agent 与 nftables。前端跑类型检查、生产构建和预览、提交、回执的浏览器流程。契约与后端纳入 `make check` 和发布矩阵。真实 VPS 配置变更不作为验收手段。
