# 代理隔离加固实施记录

## 1. 范围

2026-09-16。本次落实 [最小加固方案](security-minimal-hardening-plan.md) 的两处边界：代理读取管理数据，以及 sing-box 改 mark 绕过目的地址限制。威胁前提是代理内已有任意代码执行，不代表发现了可远程利用的入口。

改动保留在本地工作树，未提交、发布或切换生产服务。经用户授权，另在指定目标 VPS 的临时隔离容器中验证。实现和隔离测试结果如下；未测试项目不计作通过。

## 2. 已实现

### 2.1 身份、权限和启动器

默认 sing-box 使用独立的 `ctlvps-sb` 系统账户，授权私网组使用 `ctlvps-sp`，Snell 每端口使用独立系统账户。拒绝复用可登录、共享 UID/GID 或带附加组的账户。管理目录和维护 socket 对代理不可访问。

代理不再拥有 `NET_ADMIN`。sing-box 仅保留设置 mark 和绑定低端口需要的能力，Snell 仅保留低端口能力。启动器接收固定内核、固定权限组或端口和固定动作，不接收任意命令、路径。代理不能修改 root 生成的配置或证书快照。

代理运行配置位于独立的 `/etc/ctlvps-proxy`，各权限组的子目录仍按专用组限制访问。真实安装中的管理目录 `/etc/ctlvps` 可以保持 `0750`，无需放宽权限。

Go 启动器用 seccomp 限制 IPv4/IPv6 原始套接字、AF_PACKET 和 io_uring，并校验系统调用架构；过滤器同步到线程，跨 exec 继承。保留普通 TCP/UDP、NETLINK 查询以及必要的 SO_MARK。过滤器或 SO_MARK 探测失败则不启动目标内核。

### 2.2 cgroup 出站边界

两种内核都按实际 systemd cgroup 限制目标地址。sing-box 的零 mark、伪造其他节点 mark 都不再跳过边界；现有 mark 计量不变。Snell 继续按独立 slice 做 IPAccounting，不叠加 nft 计费。

不同私网授权分成两个账户、两个进程和两个 cgroup；默认只有一个共享 sing-box。保留显式私网例外、客户端回包和系统解析器 TCP/UDP 53 例外。两个进程的连接日志独立读取，再合并上传，节点 ID 不变。

root 成功安装出站规则后，才写入 `/run/ctlvps-proxy/egress-ready`，记录本次系统启动标识。代理启动器校验该文件的属主、权限及启动标识。机器重启时旧标记失效，代理必须等待 agent 安装规则，避免开机期间先启动代理、后加载防火墙。

### 2.3 运行期防火墙守护与有限计量加固

新增独立的 root systemd 定时器，每 5 秒检查一次 `ctlvps_egress` 实际规则摘要，不依赖控制端连接或 agent 轮询。root 专用策略快照绑定当前启动标识，通过进程间锁串行更新；摘要忽略 nft 重载产生的句柄和版本元数据。

规则缺失或变更时原子恢复这张不含计费计数器的表，成功时不重启代理。恢复失败则撤销启动就绪标记，先排入明确停服任务以抑制自动重启，再强制终止代理 cgroup（含无响应进程），恢复后只启动守护器曾暂停、且仍在当前期望配置中的服务。手动停服保持停止；控制端、agent、维护服务不在可操作名单中。启动标记与策略同时丢失而代理仍在运行时，也会停服，不能误判为首次安装。卸载先停定时器，再清理代理，避免清理过程中被重新启动。

这是定时检测，存在检测间隔和命令执行时间，不承诺防火墙被 root 清空后的零暴露窗口，也不能防止 root 同时禁用守护器。

用户选择保留共享 sing-box 进程。新增 cgroup 内有效节点 mark 白名单，在计费 hook 之前丢弃未知、其他权限组、已删除或已封禁节点的标记。普通组拒绝零 mark；原生 ACME 组保留零 mark 以维持其 HTTPS 请求，系统解析器 DNS 和客户端回包也保留必要例外。实际节点 ID、计量公式和正常转发不变。

此项是有限加固：共享进程被完全控制后仍可能冒用同组另一个有效节点的 mark；原生 ACME 的零 mark 例外也不具备可信节点归属。不能将普通计量隔离测试解释成已抵抗进程内任意代码执行后的串账。

### 2.4 证书与原生 ACME

自签名及外部证书经过密钥匹配和有效期检查，生成按内容命名的只读快照；更换证书会触发配置更新，旧快照留在 root 管理目录供恢复。源文件不放宽权限。

原生 ACME 使用原有账户与证书状态，通过 systemd 将原 ACME 子目录绑定到专用运行路径。代理只看见该子目录，管理父目录仍不可访问；不重新注册账户、不重复搬运证书、不新增签发服务。账户和 TLS 私钥属于代理运行必需数据，仍能被该代理读取。

已有低权限 ACME 状态不自动改归另一账户。混合私网权限同时使用原生 ACME 的配置也会在切换前拒绝，防止共享状态和挑战端口冲突；这些组合不能标记为已完成加固。

### 2.5 检查、恢复与卸载

sing-box 切换前使用真实目标身份、能力和挂载执行配置检查，检查失败保持原服务。检查进程使用独立 cgroup 和无外网网络命名空间，避免挤占运行中代理的聚合内存预算；两个实际运行权限组需要通过内存预算检查。切换保存原单元、配置及启用状态；启动失败恢复原配置和服务，并向控制端报告失败。Snell 按实例恢复，稳定计量 slice 保持运行。

首次切换需要重启代理，可能短暂断开连接。后续无配置变化不重启。未修改节点身份、密码、订阅生成方式、流量公式或配额状态。

启动后及幂等检查还会读取实际进程的 UID、有效/边界能力、NoNewPrivileges、seccomp 状态、systemd slice 和启动命令。运行态不符时报告失败，不能只凭单元文件的文本宣称加固完成。

卸载器识别新的固定启动命令和权限组 slice，仍校验自定义启动命令及覆盖配置。默认保留代理配置、证书和 ACME 数据，只有显式 `--purge` 才删除；不删除系统账户，不影响同机控制端。

### 3.1 目标 VPS 验证

2026-09-16，经用户指定，在目标 VPS 上使用临时 Docker 容器验证。目标为 amd64、Linux 6.1.0-45-amd64、cgroup v2；宿主 systemd 为 252，容器内为 255。容器无外网、不发布端口，限制 768 MiB 内存和 1 CPU，测试账户、证书、代理凭据及网络目标均为合成夹具。未修改宿主控制端、证书或代理配置。

96 项边界检查、真实 Apply 的幂等及失败恢复、证书替换、混合私网分组、六种 sing-box 协议的 24 条 IPv4/IPv6 TCP/UDP 路径、Snell 5.0.1 启动及幂等、开机就绪标记检查均通过。控制端在验证后仍为 active。该结果覆盖目标机真实内核和原生 amd64 执行；容器内用户空间不等同于宿主原生部署验收。

### 3.2 原生 ACME 测试入口

候选模式额外提供 `PEBBLE_BIN` 时，边界脚本在同一隔离容器内运行 `scripts/security-boundary-test/acme_renewal.py`。需要同时提供 `SINGBOX_BIN`。Pebble 测试 CA 验证真实挑战，签发短有效期证书；脚本等待 sing-box 自身调度续期，校验 TLS 链和域名、证书指纹变化、服务未重启、账户密钥不变及重启后的持久化。测试 CA 信任与 ACME provider 覆盖仅在容器内生效；运行约需 10 分钟。

目标 VPS 上使用 Pebble 2.10.1 完成真实 HTTP 挑战和首次签发，约 10 分钟后自动续期成功：TLS 校验通过、证书指纹改变、systemd InvocationID 未变、账户密钥不变。首次运行最后的“重启后指纹不变”断言失败；测试 CA 日志证实重启又完成了替换签发，磁盘也保存了新证书。已将断言改为核对重启后的可信 TLS 证书与磁盘一致、账户密钥保留，并使用 `--restart-only` 单独补测通过。当时自动续期与重启证据来自这两次运行；后续已在 3.4 完整重跑修正后的周期。

这验证了加固权限下的原生 ACME 挑战、签发、自动续期、热加载及状态保存，不代表公有 CA 的真实域名、DNS 和公网挑战路径已验收。

### 3.3 宿主原生验证与修复

用户随后授权目标 VPS 的真实部署验证。只读检查确认该机实际运行控制端，没有已安装的 agent 或代理内核；面板当时管理的 7 台服务器、86 个节点使用的服务器证书模式全部为自签名。本次在宿主直接创建临时代理 systemd 服务，使用当前生产 agent 二进制中的固定启动器和真实生产 Apply，不经过 Docker。没有修改控制端数据库或将其他服务器切换到新版本。

首次原生预检发现 `/etc/ctlvps` 为 `root:root 0750`，低权限代理无法读取原设计放在其子目录的配置。已将运行配置移至独立 `/etc/ctlvps-proxy`，同步固定启动器和卸载器；保留管理目录权限。容器回归新增管理目录 `0750` 条件，防止再次漏检。

修复后在宿主 systemd 252、Linux 6.1、amd64 上通过：

- 自动生成自签名证书并严格验证 TLS 链及域名。
- Trojan 真实客户端的 IPv4/IPv6 TCP/UDP 回显。
- 配置幂等、错误配置保留服务、端口冲突后的恢复与转发。
- 公网与授权私网组独立 UID、能力和 seccomp；代理账户不能读取真实管理数据库及证书源私钥。
- 官方 Snell 5.0.1 低权限启动、监听和幂等；客户端认证仍未验证。
- 控制端保持 active，InvocationID 未变。

宿主原有 IPv6 出站禁止规则令 IPv6 直连基线不可达。测试只给合成文档地址网段添加临时精确路由例外；完成后删除，原有公网 IPv6 禁止规则保持不变。因此本轮不声称该机公网 IPv6 可用。

入口为 `scripts/security-boundary-test/native.py --execute`，需要显式授权和预先提供匹配架构的生产 agent、测试 Apply 驱动、官方 sing-box/Snell。脚本拒绝已有 agent 状态、代理目录、账户、服务或端口，测试端口仅允许本机访问；通过独立 systemd 验证任务设置 300 秒运行上限和 `ExecStopPost` 清理。本轮临时服务、账户、文件和网络对象均已清理。

目录修复后重新通过核心 Go 测试、96 项容器边界检查、六种协议的 24 条转发路径、ACME 状态挂载与 systemd 生命周期、17 项卸载场景。该轮续期证据来自 3.2；随后完成的完整周期见 3.4。

用户确认保留共享进程、做有限计量加固后，重新通过 96 项边界测试、六种 sing-box 协议的 24 条转发路径、真实内核计量测试、Go 测试及 vet、17 项卸载场景。agent Go 测试所需的本地监听被沙箱拦截后，使用本地监听权限单独重跑通过。

独立防火墙守护故障注入覆盖：删除整表、清空链、不依赖 agent/控制端的自动修复、模拟规则加载失败后强制停止被冻结的代理、恢复后的选择性启动、手动停止不复活，以及策略文件和就绪文件同时丢失时停服。其他 nft 表及计数器保持不变。

Snell 认证转发使用 [OpenSnell 固定源码](https://github.com/missuo/opensnell/tree/3100984fd7c3a2bd7b41e292ad41f10d928bfb2d) 构建一次性测试客户端，作为 `SNELL_CLIENT_BIN` 传入隔离容器，以 nobody 账户运行，仅使用合成凭据。客户端不是产品依赖。它的 SOCKS UDP 回复误报 TCP 端口，测试脚本明确读取该客户端实际 UDP 监听端口；不改官方 Snell 服务端或其认证协议。正确密码下 IPv4/IPv6 TCP/UDP、TCP 复用及错误密码不能转发均通过。该证据覆盖 Snell TCP 传输及其中承载的 UDP，不覆盖 Surge 专用 QUIC 模式；未启动或修改用户的 Surge。

本次另外完整重跑修正后的 Pebble 2.10.1 ACME 流程：真实挑战与首次签发通过，约 10 分钟后由 sing-box 自身自动续期，TLS 链与域名校验通过、证书指纹变化、服务 InvocationID 不变、账户密钥不变；随后重启并核对可信 TLS 证书与磁盘保存一致、账户密钥保留，全部通过。重启时短期证书再次签发属于允许的测试行为。该结果仍是隔离测试 CA 验证，不替代以后启用公有 CA 时对实际域名及公网挑战路径的检查。

## 4. 上线门槛

目标机宿主原生代理服务及当前使用的自签名证书路径已验证；测试 CA 的自动续期也有实测证据。Snell 常规认证、TCP 和 UDP 转发已补验，Surge 专用 QUIC 模式尚未验证。现有服务器全部使用自签名证书，公有 CA 验证不作为当前功能的上线门槛；以后启用 ACME 时再验收真实域名和公网挑战路径。

旧内核若不能在无 NET_ADMIN 下设置 SO_MARK，会在 sing-box 配置预检阶段失败，保留旧服务并报告未加固，不关闭计量或恢复 NET_ADMIN 以绕过检查。混合私网授权与原生 ACME 的未验证组合保持原服务，不自动拆分。

本轮在用户指定 VPS 完成临时容器和宿主原生代理验证，未升级生产控制端或其他服务器。测试报告交付后，由用户决定下一步。
