# 统一流量计算与对账

当前发行仅支持 Linux AMD64（x86_64），ARM 支持暂停；下文 ARM 测试结果仅为历史记录，不构成当前兼容承诺。恢复支持需要真实测试机器完成验证。

[返回 README](../README.md) · [网络与计费来源](network.md)

## 1. 原始计数与配额计算

原始入站为 RX，出站为 TX，汇总为两者相加。后端以整数 bytes 保存和计算；面板输入 GiB 时，1 GiB = 1,073,741,824 bytes。原始图表始终展示采集到的入站和出站，计费选择不修改历史计数。

服务器和分享共用以下公式，各自保存计费方式，不自动继承另一方的设置。历史分享迁移后仍按原先实际生效的双向口径计算；管理员明确保存新方式才改变计费。

| 计费方式 | 计入配额的本期用量 |
|---|---|
| 双向 | 本期入站 + 本期出站 |
| 仅入站 | 本期入站 |
| 仅出站 | 本期出站 |
| 两方向较大值 | max(本期入站, 本期出站) |

分享先跨节点、跨服务器汇总本期方向总量，再应用公式。例如两段增量为入/出 100/10、10/100，较大值计费应为 max(110,110)=110，不能逐段取大后相加成 200。分享已用、剩余、占比、超额判断、配置封禁和订阅流量头都采用同一计算结果。

## 2. 页面与客户端显示

页面分别展示原始入站、出站、汇总，以及计入配额的已用量。服务器配额校准影响计费已用，不将未采集历史画到流量图中。

分享客户端通常把订阅流量头的 upload 与 download 相加。为使客户端已用量与分享配额一致，双向保留两个方向；单向只输出该计费方向，另一方向为零；较大值只输出本期较大方向，平局取入站。这些字段表示计入配额的用量，原始方向可在面板及分享 API 查看。

## 3. 校准与时间边界

校准保存服务商读数及同一数据库事务中的本机已采集方向快照。后续分别增加入站和出站增量，再使用第 1 节公式。较大值模式必须知道校准时两方向基数，才能按两方向累计值续算；历史单总量校准保留兼容行为并标记为估算。更改服务器计费方式或重置日会清除旧校准。

自动月账期以 UTC 零点和选定重置日划分，29–31 均表示每月最后一天；分享手动重置以实际操作时刻为边界。日、时账本按采样时间归属；两次采样跨越边界时，累计计数不能还原每个字节的发生时间，不凭比例拆分生成精确历史。补报的旧周期数据保留在历史账本，不消耗新周期分享配额。服务商读数与本机采样的时间、时区和采集范围不同，也可能形成对账差异。

未设置服务器月重置日时，服务器配额使用近 30 个 UTC 日期，与近 30 天图表一致；分享的重置日为 0 时则持续累计到手动重置。比较两个用量前应确认其统计周期一致。

## 4. 采集与汇总范围

服务器采集配置指定的网卡，包含系统更新、SSH 等流量；分享累计其所属节点的计量增量。固定转发有独立账本，不混入分享。不同采集对象的数值不能直接相等，也不能把服务器、节点、分享相加作为一个总账。

sing-box 的节点身份同时标记客户端连接与代理后程连接，nft 统计对应身份的非回环网络字节；Snell 与 mita 使用独立 systemd 计量组，统计组内 IP 入站和出站，可能包含回环。两种来源均包含代理后程，不需要额外乘二。分享额外复用的现有或外部节点没有这份分享专属的凭据与计量身份，不能准确区分该分享消耗；这些节点不并入分享计量，配额也不能据此保证对它们硬封禁。

计数累计值根据来源和代际转换为增量。基线、方向账本及分享已用在同一事务提交；重复上报不会重复入账，失败事务不推进基线，冻结结算批次可按 ACK 重试。计量来源切换需先结算旧来源，不能叠加 Snell IPAccounting 与 nft，不能以额外乘 2 修补口径。

网络计量记录采集边界内的网络字节，包含相应协议开销，不能据此承诺与客户端应用下载文件大小或供应商账单逐字节相同。未采集的历史和重启前未保存的内核计数无法凭后续累计读数恢复；对账结果应说明时间范围、采集来源和实际验证范围。

## 5. 验证范围

2026-09-30 在 Linux ARM64 的隔离 Docker/systemd 环境中，使用官方 sing-box 1.14.1 运行 VLESS、Trojan、AnyTLS、Hysteria2、TUIC、WireGuard、Shadowsocks 的公开订阅和分享订阅，逐项验证 TCP、UDP 与服务端先发数据。流量结束后冻结服务，独立读取 nft 内核计数，确认每个分享节点的入、出站账本与内核相等，分享已用及历史账本与所属节点总和相等；切换四种模式后，配额、剩余及订阅流量头继续一致。

回归还覆盖跨服务器先汇总再取较大值、重复与乱序上报、真实 boot 代际、来源迁移、延迟结算、编辑与入账交错、月周期重置交错、手动暂停、超额处理与管理员编辑交错，以及完整方向校准。前端测试验证共用公式、GiB 精度及 UTC 日期。这些验证不代表 Snell/mita、全部架构或真实供应商账单已逐字节验收；重现真实内核对账使用 `scripts/test-network-systemd-container.sh` 的 `subscriptions` 场景。
