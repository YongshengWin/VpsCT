# 1. Alpine/OpenRC 扩展方案

当前发行仅支持 Linux AMD64（x86_64），ARM 支持暂停；下文 ARM 测试结果仅为历史记录，不构成当前兼容承诺。恢复支持需要真实测试机器完成验证。

## 1.1 范围

被控端增加官方 mieru（mita）多实例与网页升级、卸载。控制端仍使用 Debian/Ubuntu systemd；Snell 仍不支持 Alpine。沿用现有 systemd 安装流程，不连接真实 VPS，不发布发行包。

## 1.2 mieru 服务和计量

每个端口一个固定命名的 OpenRC 服务、非 root 账号和只读沙箱。节点 ID 对应独立父 cgroup，实例重启不重置父组计量。使用内核 cgroup-skb eBPF 在 ingress/egress 累计 skb 长度，覆盖客户端与目标站点双向流量，不与 nft 监听端口计量叠加。映射和链接固定保存在 root 专属 bpffs 目录；缺少内核 BPF 能力时拒绝部署，不退回不完整计量。节点停止后读取最终计量，控制端确认结算后清理。重启通过 boot ID 区分计量世代。拒绝携带未结算 systemd 计量跨环境迁移。

## 1.3 网页维护

继续使用现有二次认证、任务领取、固定下载地址、官方校验和持久化结果。OpenRC 只允许 agent 维护。复制执行程序到维护目录，以独立会话启动，并在执行前进入 agent/proxy 服务树外的受限 cgroup；父进程收到就绪回执后才认为派发成功。独立监督进程限制任务最长 45 分钟，并在 worker 退出时清理残留子进程；agent 的 OpenRC supervisor 单独放入固定 cgroup，避免随维护任务清理。维护进程在 agent 停止、替换或卸载后继续执行和回报。升级先验证候选程序 OpenRC 能力，更新固定服务脚本，启动后检查 OpenRC 就绪及运行文件 SHA256；失败恢复旧程序和对应脚本。中断任务保留记录，不自动重放卸载。

## 1.4 验收

单元测试覆盖服务身份、隔离属性、非法命令、计量迁移和任务派发；Linux amd64/arm64 编译；Alpine 隔离容器验证官方内核、双向流量、重启保留计量、配额阻断和退役结算，以及维护进程独立性、升级回滚、保留数据/清空数据卸载。缺失的运行验收必须明确记录，不以交叉编译代替。

## 1.5 当前验证记录

2026-10-14：ARM64、Alpine 3.23、官方 mita/mieru 3.37.0 已通过 TCP/UDP、完整进程计量、服务/helper 重启连续性、停用及最终计量清理。网页维护夹具已通过升级成功、启动失败回滚、保留数据与清空数据卸载、运行中任务恢复识别和幂等结果；升级夹具使用本地构建 agent，发行校验入口有明确测试替身，不把它称作官方发行下载端到端验收。既有 sing-box/OpenRC、精确内核计量、NAT、独立网络保护和 agent 启动就绪回归通过，512 MiB 夹具未发生 OOM。Go 全仓库测试及 vet 通过，Linux amd64/arm64 agent 与控制端编译通过；AMD64 未运行容器矩阵。未提交或发布发行包。
