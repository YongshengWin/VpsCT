# v0.1.8 发布说明

[变更记录](../../CHANGELOG.md) · [运维与恢复](../operations.md) · [网络配置](../network.md) · [自动化接口](../agent-api.md)

## 1. 从 v0.1.7 升级后有什么变化

- 仅 IPv6 节点可单独登记发布地址；控制端收到匹配的 agent 应用回执后才允许导出。纯 IPv6 主机可使用经校验的离线附件。受管节点支持按来源限制访问、预览并更换端口，以及记录特定网络上不可用的端口。
- 支持转交控制端所有权、按资源委派权限、为 API key 限定可用操作。查看分享状态不等于有权读取连接凭据。成员可为自己的分享使用个人模板；公共和个人模板最多保留 30 个加密历史版本。Mihomo 可按实际出口地区生成代理组。
- 修复 AnyTLS / Trojan 在 ACME 模式下与使用 `h2` 或 `http/1.1` 的客户端协商失败。更新 agent 后重新应用即可，不必重建节点或清除证书。共享 sing-box 重载时，已有连接可能短暂中断。
- 减少 Tailscale 策略路由导致的错误计量冲突、Alpine/OpenRC 加载计量程序时的瞬时失败，以及并发写数据库导致的转发创建冲突。真实的路由冲突、端口占用和过期预览仍会被拒绝。

## 2. 升级与回退

1. 本版仅支持 **Linux AMD64**。升级前保存同一时点的控制端程序、数据库、加密密钥和配置。Docker 部署先确认持久卷和快照可用；不要把原生安装切换成容器安装来代替升级。
2. 按[运维说明](../operations.md)使用原部署方式更新控制端。数据库由 schema 41 自动迁移至 51。确认管理员可登录，核对服务器、节点、分享归属、成员权限和现有订阅。
3. 核对受管服务器的 agent 版本、在线状态及应用回执。只更新控制端不会让旧 agent 获得新能力。需要仅 IPv6 导出或 ACME 修复时，用客户端验证实际连接。代理内核仍使用所选官方版本，不因控制端升级自动追新。
4. 如需回退，停止新版控制端，恢复升级前的配套程序、数据库、密钥和配置。不要让旧程序直接读取 schema 51 的数据库。

## 3. 发布验收范围

正式附件要求同一源码树通过原生 AMD64 的 1024 个 UDP 会话、600 秒持续负载和 ACME 原生续期检查；日常 PR 的 60 秒结果不能替代。标签工作流还需对最终附件重新做安全扫描和真实历史版本网页升级测试，才会创建草稿。8192 会话仅是诊断档，不代表默认内存预算下的承载承诺。详见[发布门禁](../releasing.md#6-ci-并行与发布证据)。
