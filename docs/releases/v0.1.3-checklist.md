## 3. 发布前剩余步骤

1. 审核完整工作树与变更说明，确认全部新增文件纳入最终提交；本次改动没有变更依赖清单或锁文件。
2. 创建最终提交并在干净源码及 CI 上完成检查，包括密钥扫描、依赖漏洞扫描、ShellCheck/actionlint、浏览器安全、内核隔离和 Docker 检查。历史通过结果不能替代最终提交的 CI。
3. CHANGELOG 已登记发行日期并生成发布说明；从最终提交重建双架构附件。不要直接上传当前工作树测试产物。
4. 创建并核对 v0.1.3 标签与 Release 草稿，再公开发行；从未登录环境核验附件、校验和以及 latest 安装入口。

## 4. 升级说明

1. 数据库从 schema 9 升级至 11。先备份数据库及密钥，先控制端后 Agent；回退需配套的数据备份。
2. Agent 自动同步可能短暂重启。旧 systemd 单元的资源限制及独立卸载脚本，需通过新版安装器安装或终端更新落地。
3. 删除服务器默认同时卸载，经过二次认证且收到成功回执才删除记录；离线或失败时保留。没有控制端的旧 VPS 可下载官方独立卸载脚本，不需要重新注册。
4. ARM64 交叉编译与容器检查不能替代目标环境实机验收；未声称完成全协议、大规模并发或长期生产稳定性验证。
