# v0.1.5 发布说明

[返回变更记录](../../CHANGELOG.md) · [发布验收清单](v0.1.5-checklist.md) · [候选验收记录](v0.1.5-validation.md) · [发布流程](../releasing.md)

## 1. 状态与范围

本说明汇总相对 v0.1.4 的改动，发行日期为 2026-09-24，实际公开状态以 GitHub Release 为准。功能实现、阶段测试通过和正式发行验收分别记录，不将开发构建视为正式附件。

本轮覆盖网络观测与计费、节点网络与双端中转、固定 TCP 转发、新协议与订阅兼容、官方内核适配和升级体验，以及相关安全、维护与文档整理。日常操作见 [网络指南](../network.md)、[节点与订阅](../subscriptions.md) 和 [运维文档](../operations.md)。

## 2. 网络观测与服务器计费

### 2.1 多网卡状态与历史

- 增加网卡类型、MAC、MTU、上下级关系、本机地址、链路状态和 IPv4/IPv6 默认路由观测；展示各接口 RX/TX、速率、累计值与历史。
- 接口使用稳定身份，改名保留历史，删除重建不继承旧绑定；计数倒退或观测连续性丢失后重新建基线。
- 离线与采集失败显示历史状态，不伪造零流量；网桥、veth、回环可切换显示。消失接口支持分页查看与归档，再出现时自动恢复，保留账本。
- 新旧 agent 通过能力协商传输网络快照，观察失败不阻断原心跳和配额流程。

### 2.2 计费接口切换

- 支持选择 1–16 张接口，检查在线能力、快照完整性和拓扑重叠，预览后确认切换。
- 使用同一快照结算旧来源并建立新基线；冻结批次、策略版本和回执持久化，重复上报不会重复计费。
- 缺卡、身份变化、拓扑异常及旧策略数据不会触发隐式回退；记录异常和恢复。
- 服务器配额仍按入站加出站计算。出站接口与计费接口独立，节点、分享及转发账本不重复合并计费。

## 3. 节点网络与出口管理

### 3.1 监听、出站和访问地址

- 已部署节点分别设置本机监听地址、出站规则固定版本与客户端访问地址；支持显式恢复默认。
- 校验接口身份、源地址归属、地址可用性、地址族、agent 能力及内核版本。只指定源 IP 不等于改路由。
- 出口支持 direct、SOCKS5、SS-2022、SSH、WireGuard，提供结构化配置、加密凭据、保留认证编辑及凭据轮换。
- 出口以不可变版本引用，编辑不自动改写已有节点；停用、删除和重新绑定前显示依赖与共享进程重启影响，提交时再次核对。
- 操作状态区分等待、失败、重试与匹配回执后的应用成功；历史操作与配置代次关联。

### 3.2 解析、运行保护与恢复

- 域名上游通过受限启动解析与 TTL 刷新；相同地址续期不重启，地址变化先阻断旧路径再应用。
- agent 保存最新网络意图，支持控制端离线期间刷新与重启恢复；旧缓存、不同服务器、摘要不一致或本机策略不满足时拒绝恢复。
- 持续监测接口与地址，健康租期到期自动阻断；防火墙规则漂移修复后须重新确认健康，不重放旧许可。
- 私网上游使用 VPS 本机端点窄授权，业务私网开关不能替代。授权撤销、危险解析和接口失效不回退直连。

## 4. 双端中转与固定转发

### 4.1 托管 WireGuard / SS-2022 中转

- 从入口节点选择落地 VPS，自动创建独立落地服务和入口出口绑定；高级设置提供连接地址、网卡和 DNS。
- 落地端确认应用后才推进入口；任务持久化，重启续办，校验两端最新配置和维护互斥。
- 退役先阻断入口，再撤销落地、结算流量并释放端口；入口保留停用引用，须显式解除才能恢复默认路径。
- 活跃中转保护两端服务器与托管出口，避免直接删除或从普通出口编辑器改写。已退役记录可从常用列表移除，仍能查看历史。
- 托管落地支持域名和符合本机授权的私网地址。

### 4.2 固定 TCP 端口映射

- 提供独立固定转发资源、来源限制、连接预算、端口预留、直连 IP/域名目标及适配的传输出口。经传输出口当前要求固定 IP 目标。
- TCP 转发有独立计量、冻结批次、清理收据与去重结算；修改或删除后，旧端口直到最终清理确认才释放。
- 私网固定目标采用独立本机授权。配置修改、保护规则恢复和退出流程不绕过连接准入限制。
- **UDP/TCP+UDP 固定转发暂不开放**：官方内核空闲映射回收未通过验证。旧记录保留，可停用、删除或改为 TCP；新阻断配置应用后撤下旧 UDP 监听。普通节点和托管中转的 UDP 不受此限制。
- **TCP 半关闭仍有限制**：官方 1.14.1 的对应实验未通过，依赖发送 EOF 后继续接收响应的应用须单独验证。

## 5. 协议、订阅与分享优化

### 5.1 新协议与配置输出

- SSH 客户端和服务器出口支持密码或内联私钥，强制主机公钥校验；只支持 TCP，提供 Mihomo 与 sing-box 配置，不虚构通用 URI。
- WireGuard 支持外部出口、单用户接入、受限标准配置导入和客户端输出；sing-box 使用 endpoint 格式，拒绝不能等价转换的参数与配置脚本。
- mita 自动部署支持 TCP/UDP 传输、业务计量、凭据轮换和删除，Mieru 提供结构化编辑与 Mihomo 输出。
- Snell/mita 支持指定监听地址、独立运行保护和分享新入口继承；业务出站仍使用宿主机路由，暂不支持传输出口。
- 节点详情按协议展示有效客户端片段；没有 URI 或不支持的格式不再显示无效输出入口。

### 5.2 订阅兼容与模板修正

- Shadowrocket 的 Snell 使用原生 `password` 等字段，保留版本、混淆、UDP、复用与链式配置。
- Mihomo 输出排除不支持的 Snell 高版本与依赖链，保留节点库原版本；不通过改写版本号伪装兼容。
- 导入、外部同步、分享和链式渲染过滤完整匹配的流量/到期信息伪节点；只有信息项的同步响应不会清空已有真实节点。
- 模板地区标记没有匹配节点时，自动生成的空组回退到该订阅可用节点；有匹配时仍按地区选择，显式 DIRECT 保持不变。
- 浏览器直接访问订阅、显式格式或短链接显示使用提示，返回不缓存的 403 页面；正常客户端继续按格式获取配置。此行为不替代 token 保密与访问控制。

### 5.3 分享网络继承

- 分享目标可保存网络模板，新专属入口复制监听设置和固定出口版本。
- 已有入口、凭据重签和恢复不随模板后续修改自动改线；WireGuard Peer 私钥不能作为共享模板复用。
- 普通节点与分享专属节点均纳入公开模板订阅验证，保持独立凭据、原流量口径和暂停过滤行为。

## 6. 官方内核、升级与部署兼容

### 6.1 仅使用官方内核

- sing-box 仅适配、下载官方发行包，不修改、自行编译或在 VpsCT 发行物中附带定制内核。
- 普通网络绑定兼容官方 1.12.14 起的 1.12.x、1.13.x、1.14.x 稳定系列；SS-2022 出口与托管 SS-2022 要求 1.14.1 起的适配 1.14.x。
- 允许兼容系列补丁升级；网络资源拒绝未知系列、预发布及自定义后缀。已有 SS-2022 依赖时，阻止降级到不支持该能力的版本。
- 1.14 配置适配 `certificate_provider`，移除不再需要的 `independent_cache`，旧系列保留对应配置格式。

### 6.2 固定版本与升级反馈

- 新库锁定 sing-box 1.14.1；旧库显式选择保持不变，未设置或空值固定为原默认 1.12.14。启动迁移在事务内完成，读失败不覆盖旧配置，重复启动不重新选择版本。
- 设置页主动保存默认选项时也保存具体版本；浏览页面、创建草稿和升级面板不会自动升级内核。
- 管理员可见兼容性升级建议，关闭偏好按账号、浏览器和建议版本保存；没有 sing-box 受管服务器时不显示。
- 设置页展示各服务器实际版本、等待、离线和异常状态。选择建议只改表单，保存后才下发；匹配最新版本、配置回执和运行状态后才确认完成。
- agent 能力协商和候选程序兼容检查覆盖新增网络资源，防止更新到无法处理现有资源的程序。相关安装、维护、卸载清理范围随新资源扩展。
- 新版官方 Linux 包需要兼容的 glibc 环境，本轮运行验证使用 Ubuntu 24.04，不能把它当成 Alpine 静态程序使用。

### 6.3 反向代理与文档

- Host 校验按站点协议规范化默认端口；仅在配置站点地址且相邻代理可信时接受单一、由代理覆盖的 `X-Forwarded-Host`，保留跨站与异常 Host 拒绝。
- 域名不匹配提示补充站点地址和 Nginx Host 配置定位方法。
- README 保留产品使用入口；网络、订阅、运维、阶段实施记录和版本发布说明各自归档，版本能力不在主页单独展开。

## 7. 升级与回退

1. 当前源码数据库迁移到 **schema 30**；v0.1.4 使用 schema 11。正式打包前再次核对最终迁移数。
2. 停服备份控制端完整数据目录，保留数据库、加密密钥与恢复材料；agent 本地状态含身份、最新网络意图和待结算数据，按运维流程保留。
3. 先升级控制端，再确认 agent 与维护组件能力。普通旧 agent 可继续原协议心跳，但新网络功能必须通过能力预检；不能仅凭版本文字判断可用。
4. 按 [内核升级步骤](../operations.md#47-内核版本与升级确认) 选择并保存满足功能要求的官方版本，逐台核对实际版本与应用回执，最后验证客户端连通。
5. 已有 systemd 单元与独立脚本如需更新，应通过安装器落地；自动替换 agent 二进制不等于更新全部安装布局。
6. 跨数据库版本回退使用对应旧程序和配套数据备份，不能仅覆盖二进制；新网络资源须先按退役流程处理，不能删除本地未确认的计量状态后降级。
