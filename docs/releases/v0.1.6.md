# v0.1.6 发布说明

[返回变更记录](../../CHANGELOG.md) · [安装、升级与恢复](../operations.md)

## 1. 修复范围

### 1.1 节点可连接但域名请求失败

部分 Linux 主机没有安装 systemd-resolved。升级到 sing-box 1.13 / 1.14 后，本机 DNS 可能选择 D-Bus 解析，报 `org.freedesktop.resolve1` 不存在；此时 agent 在线、内核运行和协议握手成功都不能证明代理请求可用。

新版 agent 为 sing-box 1.13 及以上稳定版生成 `prefer_go: true`，使用系统 DNS 上游，不再依赖该 D-Bus 服务；sing-box 1.12 继续省略不支持的字段。字段行为见 [sing-box 官方说明](https://sing-box.sagernet.org/configuration/dns/server/local/)。不会修改系统 DNS、节点密码或管理员选择的内核版本。

### 1.2 手动恢复后仍显示升级失败

控制端确认 agent 在线，且上报的运行文件 SHA256 与当前分发文件一致后，隐藏历史升级失败横幅。维护操作历史仍保留原结果；离线、文件不一致、状态查询失败、执行中的维护任务和卸载失败不因此隐藏。

## 2. 升级步骤

1. 使用本版控制端安装器执行 `--update --auto-rollback`，保留账户、服务器与订阅数据。
2. 确认相关 agent 同步到 v0.1.6；有失败同步记录或本地版本锁时，按维护提示重试或使用本版官方 agent 安装器更新。
3. agent 启动后重新生成节点配置。无需重新创建节点、修改订阅地址或重置凭据。
4. 使用真实客户端验证含域名的 HTTP 和 HTTPS 请求；同时确认配置回执、运行内核与文件版本，不能只检查进程是否 active。

本版不新增数据库迁移，沿用 v0.1.5 的 schema 30。sing-box 继续使用官方发行文件，本版不要求再次升级内核。

## 3. 验证与限制

- 本地通过 core/corecompat 回归、前端类型检查与构建；覆盖 sing-box 1.12、1.13、1.14 的 DNS 配置差异。
- Chrome 自动化验证已恢复 agent 的横幅消失且历史保留，以及离线、文件落后和卸载失败仍提示；原有登录、CSRF、CSP 和网络页面回归通过。
- 两台受影响 Linux 主机应用同一 DNS 配置后，真实 AnyTLS 客户端以证书校验分别完成三个 HTTP/HTTPS 请求，均返回 204。这是节点代理链路验证，不等同于所有客户端与协议验收。
- 最终源码的全量检查、双架构构建、容器与网络验收由 PR 和发行标签 CI 执行；实际发行状态及运行结果以 GitHub Release 与 Actions 为准。
- 不包含对所有隔离下载失败的根因修复；下载问题仍须查看维护日志。v0.1.5 已说明的其他网络能力限制继续适用。
