# 代理两处隔离缺口的最小加固方案

## 1. 范围与结论

后续代码实现和新增实测结果见 [实施记录](security-proxy-hardening-implementation.md)。本页保留方案设计时的验证范围。

2026-09-16。只修复已复现的两处边界：代理能读取管理数据；sing-box 可改 mark 绕过出站限制。前提是攻击者已能在代理进程内执行代码，不是已发现远程入侵入口。原始证据见 [验证记录](security-boundary-verification.md)。

候选方案已在隔离容器验证关键机制，并通过真实 sing-box 的一条完整 TLS 转发链路。**这不是产品修复已合入，也不是全部协议、ACME 续期及所有机器都通过验收。** 本次没有修改产品运行配置或连接真实 VPS；不新增多签、归档面板、签发服务或通用架构重构。

## 2. 修复方案

### 2.1 代理与管理数据分开

- 控制端、root agent 和现有维护 worker 的职责保持。代理改用专用系统账户；默认 sing-box 一个账户，Snell 每实例一个账户，需要独立私网权限的 sing-box 使用不同账户。
- 账户由本机安装/协调代码创建，禁止登录，不加入 ctlvps 管理组，不复用 nobody。已有同名账户不安全时拒绝迁移。
- agent 状态、发布信任状态、维护状态保持 root 专有。代理不得读取这些文件、连接维护 socket，也不得写整个 agent 数据目录。
- root 生成最小运行目录，目录 root:实例组 0750，配置及必要私钥 root:实例组 0640；只有 root 能替换配置与证书。源文件不随之放宽权限，不能递归 chown 共享目录。
- 日志与必要运行状态使用单独的实例目录，由该实例写入，agent 仍可读取日志。保留原有节点 ID、端口、密码、订阅、配额与计量状态。

### 2.2 能力与原始套接字

- 去掉代理宿主 NET_ADMIN。Snell 不因 IPAccounting 获得该能力，计量由 systemd 维护。
- sing-box 仅在实测 SO_MARK 成功后保留 NET_RAW；低端口需要时保留 NET_BIND_SERVICE。Snell 最终能力按实际需要单独验证，不能照搬 sing-box 的 NET_RAW。
- 保留 NET_RAW 时，同时以固定启动器安装参数级 seccomp 规则：拒绝 AF_PACKET，以及 AF_INET/AF_INET6 的 SOCK_RAW（包含 CLOEXEC/NONBLOCK 标志），保留合法 NETLINK 查询。过滤器跨 fork/exec 继承，安装失败不启动代理。
- 启动器只接受本机固定内核路径、固定配置位置及 check/run 动作；网页不能传任意可执行文件或过滤规则。不增加通用 root 命令入口。
- 保留 NoNewPrivileges、ProtectSystem、ProtectControlGroups 等现有约束。不能只靠一个 systemd 安全评分证明隔离。

### 2.3 网络规则改按受管 cgroup 判断

- 使用 agent 读取到的实际 systemd ControlGroup 路径建立规则，不相信代理上报的路径或节点 ID。受管父 slice 先建立，规则先加载，最后启动代理。
- sing-box 默认进程建立与 mark 无关的目的地址边界；零 mark、其他节点 mark 都不能跳出该边界。mark 继续参与现有计量，不变更计费公式。
- Snell 保持已有的每节点 cgroup 匹配；去掉修改防火墙的能力，避免规则可被进程自己改写。
- 保留代理客户端的合法回包。系统 DNS 例外只允许 root 信任的解析器地址及 TCP/UDP 53，不能由代理配置扩大。规则仅操作本产品表，不清空整机 nft。
- 默认仍只有一个 sing-box 进程。只有同机节点确实有不同私网权限时，才按等效权限分组，并使用不同 UID/cgroup。不能仅靠共享进程中的不同 mark 宣称权限隔离。
- 保留 root 显式授权的私网语义。当前 PrivateNodes 属于较宽的例外，不能在此次修复中偷偷改成更窄的目标名单；其风险应在迁移差异中说明。更细目标白名单属于另行需求。

### 2.4 证书兼容，不重做签发系统

- 自签名仍由原逻辑生成。外部证书仍使用本机证书 ID。root 检查普通文件、链接边界、证书/私钥匹配及有效性，再复制到实例只读运行目录；失败不切换有效旧快照。
- 保留 sing-box 原生 ACME。仅将其必要状态从 agent 管理目录迁到该实例专用目录，保留账户与已有证书，不因迁移重新注册或重复签发。原目录留作本次恢复，不直接删除。
- **原生 ACME 的账户密钥仍属于代理所需运行状态，可被该代理读取。** 本次隔离的是管理凭据，不宣称把代理与其自身 TLS/ACME 密钥隔离；因此无需新增独立签发服务。
- 同一机器若要拆多个 sing-box 权限组，必须先验证 ACME 的挑战端口、账户状态与同域证书使用没有冲突；不能直接把共享 ACME 目录交给多个用户读写。未验证的组合不自动迁移，也不算修复完成。
- 证书更新采用完整快照后激活，不先覆盖一半证书/私钥。只使用固定内核版本实际支持且经过测试的重载方式；需要重启时必须明确会短暂断开已有连接。

## 3. 已验证什么

候选模式通过 `CTLVPS_BOUNDARY_MODE=candidate SINGBOX_BIN=/path/to/verified/sing-box bash scripts/test-security-boundary-container.sh` 运行。默认模式继续复现原缺口，形成对照。容器无外部网络，全部凭据和目标均为合成数据。

| 项目 | 当前证据 |
|---|---|
| 原配置对照 | root 可读管理夹具；sing-box 改 mark 可绕过；能创建 nft 测试表 |
| 低权限候选 | 管理文件读写、维护 socket、nft 修改均被拒绝 |
| SO_MARK | 去掉 NET_ADMIN 后，专用非 root 用户仍能设置四种测试 mark |
| 原始套接字 | IPv4/IPv6 RAW 和 AF_PACKET 被拒绝，NETLINK RAW 查询套接字可创建 |
| cgroup 防绕过 | 默认组和 Snell 组不能用任何测试 mark 访问本机/私网/仿元数据目标；公网分类目标正常 |
| 私网分组 | 单独授权的私网组仍可访问测试私网；不会扩大默认组权限；共 96 项 TCP/UDP 回显检查 |
| 真实 sing-box 1.12.14 | 非 root 配置检查、参数级过滤、443 监听、证书验证、Trojan 转发、日志写入、证书替换后重启成功 |
| 计量标记路径 | 真实转发使用 SO_MARK，nft 对应 mark 计数器有实际字节增长；不是完整账单精确性验收 |

环境为 Linux arm64，内核 `7.0.14-orbstack-00380-ga7e0a2dc9535`。候选组在测试中共用一个非 root 测试账户，以验证对管理数据的隔离；实例间不同 UID 的隔离仍属实施验收项。候选使用现有 cgroup 规则生成器验证匹配机制，未把正式 sing-box 生成器切换为新实现。Python/libseccomp 启动器只用于验证，不作为生产依赖交付。

未验证项：真实 ACME 签发/续期、实际 Snell 二进制与客户端、其他部署协议、IPv6 转发与 DNS 例外、完整计量对账、旧内核及原生 amd64。证书替换测试不能冒充 ACME 续期测试，Trojan 成功不能替代全部协议通过。

## 4. 实施与切换

| 落点 | 最小改动 |
|---|---|
| core/systemd、安装/卸载 | 专用账户、最小目录、能力列表及固定过滤启动器；卸载按所属端清理，不删除其他端文件 |
| core/singbox、snell、certs | root 准备运行配置和证书快照；原生 ACME 必要状态迁移；必要时按权限组生成实例 |
| nft/egress、agent apply | 读取实际 cgroup、加载防绕过规则，再启动新进程；保留 mark 和原计量实现 |
| 日志/配置映射 | 只有新增权限组时才增加日志来源，保留节点 ID 和去重游标，不清零已有计量 |
| 测试 | 将本次允许越界的复现断言变成拒绝断言，并加入正常功能和恢复验证 |

切换顺序固定为：只读能力预检 → 保存原配置、权限、证书、规则和计量边界 → 准备新账户/快照 → 用目标身份检查配置 → 建立新规则 → 最后计量采样 → 重启目标实例 → 验证连接与计量 → 提交迁移状态。

原服务停止之前必须通过能力、空间、资源、证书及规则预检。配置检查或规则加载失败时原服务继续；切换后检查失败则恢复原配置/权限/规则/证书和运行方式，并标记“未加固”，不能显示成功。恢复不得重置配额或重复计费。只触及失败实例，不重启整机。

首次身份切换需要重启代理，不承诺零连接中断。生产切换另选维护窗口，不在设计或本地验证时自动执行。

## 5. 准入和验收标准

| 条件 | 决策 |
|---|---|
| 实际 SO_MARK、cgroup、过滤器、协议与证书检查均成功 | 可进入该机器的迁移验收 |
| 旧内核不能在无 NET_ADMIN 下设置 mark | 停服前拒绝本次迁移；保留原服务，明确尚未加固。不关闭计量、不重新授予宿主 NET_ADMIN、不自动升级内核 |
| 混合私网权限需要拆分，但内存预算不足或 ACME/端口冲突未验证 | 保留原模式；该机器不能算本轮修复完成，不静默增开无限进程 |
| cgroup/nft 受限，无法建立规则 | 不启动新模式；不降级为只看 mark |

最终放行必须同时满足：

1. 管理文件、维护 socket、nft/路由修改及原始套接字负向测试全部拒绝；默认组在零/伪造 mark 下仍不能访问禁止目标。
2. 该机器实际使用的协议、IPv4/IPv6、TCP/UDP、DNS、低端口和已授权私网访问正常。共享代码影响的其他受支持协议也须在固定版本测试，不涉及仅导入格式。
3. 自签名、外部证书更新、原生 ACME 完整续期和服务重启正常；多权限组组合单独验证。
4. sing-box mark 计量、Snell IPAccounting、分享归属、配额，以及切换前后计量连续性保持。Snell 不叠加 nft 计费。
5. 注入配置错误、证书错误、规则加载失败和进程启动失败，能保持或恢复原功能；明确哪些路径只允许在维护窗口执行。

只要其中一项未通过，就不能声称“验证好、可直接上线”。当前交付的是有关键实测依据的完整实施方案，尚未满足全部生产放行条件。

## 6. 依据

- [Linux socket(7)](https://man7.org/linux/man-pages/man7/socket.7.html)：SO_MARK 在 Linux 5.17 起可使用 NET_RAW；实际兼容仍以能力探测为准。
- [Linux raw(7)](https://man7.org/linux/man-pages/man7/raw.7.html)：NET_RAW 可用于原始套接字，不能只移除 NET_ADMIN 而忽略它。
- [sing-box TLS](https://sing-box.sagernet.org/configuration/shared/tls/) 与 [ACME](https://sing-box.sagernet.org/configuration/shared/certificate-provider/acme/)：配置与证书生命周期参考；网站覆盖新版本，实施以固定版本源码和实际测试为准，不直接照搬新版格式。
