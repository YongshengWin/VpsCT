## 2. 已落地范围

| 范围 | 当前实现 | 边界 |
|---|---|---|
| 网络子进程 | 专用 ctlvps-net 本地用户；拒绝账户冲突、交互 shell、复用主组；空附加组、无有效能力、NoNewPrivileges | 未改变代理服务 root 身份，不能称为代理隔离完成 |
| 精确撤销 | TUF 签名的累计 security-policy 目标；单调序号、有效期、精确摘要、代次底线；离线回退重验 | 断网只能知道本机已接收的撤销 |
| 安装文件验证 | 控制端验证签名压缩包时建立 root 状态清单；回退检查实际文件、权限、所有权、缺失/额外文件及链接 | 旧安装缺清单时须验证原始受信包，不能信任目录自报摘要 |
| 标准维护恢复 | 停服前确认安全恢复点；固定摘要、来源和三十分钟事务授权；切换中策略过期可恢复，新增撤销仍阻止 | 非标准路径的旧自更新通路和所有崩溃阶段的自动恢复尚需补齐 |
| 日志与空间 | 每任务最多两个 4 MiB 日志；诊断 128 MiB、100 条/90 天清理；保留活动任务、状态和恢复材料；检查空间/inode并实际预分配 | 预留释放后其他系统进程仍可能消耗空间，不构成跨系统配额保证 |
| 发布运维 | 新根 2-of-3，轮换校验新旧阈值；CLI/CI 必须显式提供累计策略；agent 上报 72/24 小时和过期提示 | 生产根分散保管、续签任务、告警投递尚未配置 |

控制端预留预算包含数据的多份快照/恢复副本、每条目录记录的额外余量及 WAL/迁移余量；剩余保留线为 max(256 MiB, 容量的 5%)。文件系统未报告固定 inode 池时，执行实际文件创建探测；有固定池且余量不足仍拒绝。预算不足不停止原服务，不自动删除用户备份。

日志预算目前为本机代码默认值，尚未接入本机配置。历史任务结果保持幂等，数量达到 10,000 后拒绝新增维护；归档工具、完整存储用量面板及明确备份保留策略尚未完成。健康检查成功也不再自动删除上一份 agent 程序。

## 3. 本批验证

| 验证 | 结果/覆盖 |
|---|---|
| scripts/check.sh | 前端测试、类型检查和构建、Go vet/全量测试、主机和 Linux 双架构编译、安装/卸载参数检查通过 |
| race | secureupdate、maintenance、diskbudget、agent 通过 |
| 系统维护容器 | Ubuntu 24.04 / Linux arm64，真实 systemd；正常升级、程序及数据回退、受损恢复文件停服前拒绝、agent 更新/回退、两端清空隔离等 11 项通过 |
| Release 安装器 | 安装/初始化、更新、损坏包、失败恢复、旧数据保持和 Caddy 分支通过；未签发公网证书 |
| 网络身份实际执行 | 一次性 Linux arm64 容器通过：独立 UID、空附加组、零有效能力、NNP、root 私有文件读写拒绝、冲突账户拒绝 |
| 真实浏览器 | Chrome：正常初始化/管理写入、外部证书 ID 部署、跨站/同站子域攻击、CSRF、CSP 与 iframe 防护通过 |
| amd64 运行 | 已编译测试程序，但本机容器返回 exec format error；未获得运行验收证据 |
| 单元负向 | 累计撤销不可遗忘、序号/代次不可倒退、离线撤销持久、事务中到期/新撤销、安装文件篡改/链接、日志洪泛/遗留超大文件、磁盘/inode预算 |
| 静态检查 | ShellCheck、actionlint、Python 夹具解析、git diff --check 通过 |

本批未新增依赖。初次容器回归暴露了 GNU df 参数组合与动态 inode 统计的兼容问题，已修正；失败均发生在停服前。测试初始安装也改为先真实验签，不再依靠手工复制未登记程序。

## 4. 尚未完成的工作与发布门禁

1. H01：代理专用身份、最小证书快照、独立 ACME 账户边界、配置检查及完整权限恢复。

3. H03/H04：非标准自更新路径、崩溃阶段恢复演练、归档与保留策略、用量与迁移状态界面。
